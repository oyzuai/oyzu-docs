Manage your first tool

Oyzu treats the tools a project needs (compilers, runtimes, package managers) as part of the project. It works out the requirements, resolves exact versions into a lock file, installs them with verification, and runs your commands with them, so the same project builds the same way on every machine.

Where requirements come from​

In order of preference:

  1. Native pin files your ecosystem already has: rust-toolchain.toml, go.mod, global.json, the packageManager field, Gradle and Maven wrapper properties.
  2. oyzu.toml, for anything a native file cannot say, or limits for a folder or team.
  3. oyzu.lock, which records the exact resolved versions and digests.

Never copy a version into two places. If a native file already says it, say it there.

Lock and install​

oyzu pin        # resolve and record exact versions in oyzu.lock
oyzu install    # install what the lock selects
Tool installation

Tool  Version  Result
go    1.27.3   reused

Selected installations verified. Use oyzu tools current to inspect availability.

oyzu install verifies each download against recorded digests and publisher evidence before using it. Installed tools are then trusted: they are not re-hashed on every command. A build also acquires supported missing tools by itself, so oyzu build works on a fresh machine. Commit oyzu.lock so teammates and CI get identical versions.

To add a tool by name, oyzu install go@1.26 declares, locks and installs it in one step. oyzu update moves locked versions forward within their existing requirements, and oyzu uninstall removes a declaration.

Use the tools​

oyzu which go
oyzu exec -- go version
…/Oyzu/tools/installs/<digest>/payload/bin/go.exe
go version go1.27.3 windows/amd64

oyzu which shows exactly which verified executable would run. oyzu exec -- <command> runs any command inside the frozen tool environment, which is how you run ad-hoc commands with the project's toolchain without installing anything globally.

To have your normal shell pick these tools up whenever you are in the project:

oyzu shell install bash     # or: zsh, or: pwsh --rc-file $PROFILE

Open a new terminal afterwards. IDEs and scheduled jobs can use shims: run oyzu reshim and add the folder it reports to PATH.

Inspect and troubleshoot​

oyzu tools current          # requested vs selected versions and their source
oyzu tools list             # what is in the tool store and what references it
oyzu tools versions go      # versions that could be installed, and why others are excluded
oyzu tools info go          # provider, source, verification, eligibility

Provider and platform coverage is bounded, so not every tool installs automatically yet; when one cannot, the command says what is missing instead of guessing. Details: tool commands, tool management, shell activation, configuration.
