Tutorial: build your first project

In about ten minutes you build a tiny Go program with Oyzu: you see what Oyzu detects, preview the build, build and test it, check the result, rebuild it from cache and read a failure. The output on this page comes from a real run on Linux; your times, hashes and paths will differ.

You need the oyzu executable (Install Oyzu) and network access for the first build, so Oyzu can download Go. You don't need to install Go yourself.

1. Create the project​

mkdir hello && cd hello
git init

Create go.mod:

module example.com/oyzu/hello

go 1.22

Create main.go:

package main

import "fmt"

func greeting(name string) string { return "Hello, " + name + "!" }
func main()                       { fmt.Println(greeting("Oyzu")) }

Create main_test.go:

package main

import "testing"

func TestGreeting(t *testing.T) {
	if got := greeting("Oyzu"); got != "Hello, Oyzu!" {
		t.Fatalf("unexpected greeting: %q", got)
	}
}

That's the whole project. There is no Oyzu configuration file: Oyzu works from the files Go already uses.

2. See what Oyzu found​

Target names are what `oyzu build <target>` accepts.
Next steps:
  oyzu run list      every task and the command it runs
  oyzu build --plan  preview the build stages without running them
Use --json for the complete discovery record, including each task's environment and dependencies.

Oyzu found one Go application, which it calls project. It only read files; it ran nothing. To see the commands behind each task:

$ oyzu run list

Commands show argv; task dependencies and hooks may also run. Use --json for full task records.

These are ordinary Go commands. You can run any of them with oyzu run, for example oyzu run test.

The plan shows what a build would do without doing it. Two things to notice:

  • Oyzu needs Go 1.22 or newer, and it read that from the go 1.22 line in go.mod.
  • A plain oyzu build runs only the build stage. Tests, lint and format checks are skipped to keep local builds fast. --full turns them on.

Output shortened. Read it from the top:

  • Prepare loads configuration, picks the Go version and installs it. Here Oyzu downloaded Go 1.22.12, the newest 1.22 release, and checked it against its published digest.
  • Plan shows which stages run for each target.
  • Build has one row per action, with the real command (go build, go test, go vet, gofmt -l), the result and the time.
  • Outputs lists the program Oyzu built.
  • The last lines summarize the tests that ran, coverage and the overall result.

The build added two things to your project:

PathWhat it isCommit it?
oyzu.lockThe exact Go version and download digest Oyzu usedYes, so everyone gets the same Go
dist/The output bundle: the program, test reports, logs and a manifestNo, add it to .gitignore

inspect confirms that every file in dist/ is exactly the file the build recorded, by comparing digests. It tells you the bundle is intact. It doesn't tell you who built it, and the last line says so.

Change "Hi, " back to "Hello, " and the build passes again.

What you learned​

CommandWhat it does
oyzu discoverShows the targets Oyzu detected and which builder handles each, without running project code
oyzu run listLists the tasks Oyzu found and the command each runs
oyzu build --planPreviews stages and tool needs without running anything
oyzu build --fullBuilds, tests, lints and format-checks; writes dist/ and oyzu.lock
oyzu historyLists past builds
oyzu inspect distChecks the output bundle against its recorded digests
