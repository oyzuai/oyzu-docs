Your first build

Run these four commands from the root of an existing Rust, Go, Node, Java, Python, .NET, Docker or Helm project. You don't need a configuration file. For a step-by-step walkthrough with full output, see the tutorial.

oyzu discover         # 1. what Oyzu found
oyzu build --plan     # 2. what a build would do
oyzu build --full     # 3. build, test, lint and format-check
oyzu inspect dist     # 4. check the output

1. See what Oyzu found​

$ oyzu discover
1 target · 6 tasks discovered without running project code
Project root: ~/hello
​
project · go/app
  Chosen by          detected from project files
  Location           .
  Manager            go
  Version            0.0.0
  Part of builds     build, format-check, lint, test
  Development tasks  format, install
​
Target names are what `oyzu build <target>` accepts.
Next steps:
  oyzu run list      every task and the command it runs
  oyzu build --plan  preview the build stages without running them
Use --json for the complete discovery record, including each task's environment and dependencies.

Oyzu reads your native files (Cargo.toml, go.mod, package.json, pom.xml, pyproject.toml and so on) and lists each target (a buildable unit, here project), the builder that handles it and its tasks. It runs none of your code to do this. oyzu run list shows the exact command behind each task.

2. Preview the build​

oyzu build --plan shows which stages run for each target (build, test, lint, format check) and which tool versions they need. It installs, downloads and runs nothing.

3. Build​

oyzu build            # fast local build: build stages only
oyzu build --full     # also run tests, lint and format checks

The first build picks tool versions, writes them to oyzu.lock and downloads any tools that are missing. The output has the same sections every time: Prepare, Plan, Build (one row per action) and Outputs, then a result line. A failed action gets its own section with the error, the exit code, the log file and a command to re-run just that target.

oyzu build exits with 0 on success and non-zero on failure, so it works in scripts and CI. Add --json for machine-readable output.

Commit oyzu.lock and add dist/ and .oyzu/ to .gitignore.

4. Look at what happened​

oyzu history          # past builds
oyzu inspect dist     # check the output bundle against its recorded digests

Build again without changes and Oyzu reuses the earlier results, and labels them as reused. See Read your build results.

If something goes wrong​

ProblemWhere to look
A tool is missing or can't be installedManage your tools
The build failsThe failure section and the log it names, then Troubleshooting
A target is missing or uses the wrong builderAdd a small build.yaml: Adopt Oyzu in an existing repository
