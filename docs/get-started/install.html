Install Oyzu

Oyzu is a single executable, oyzu. It needs no account, agent, daemon or desktop app.

No packaged release yet

There is not yet a published installer, package-manager formula or binary download, so this page documents building from a source checkout. The verified local engine-package workflow below does not imply an official published binary distribution. When a verified distribution exists, this page will lead with it.

What you need​

  • A checkout of the Oyzu repository.
  • A Rust toolchain. You do not install it by hand: the repository's bootstrap script uses the version pinned in rust-toolchain.toml.
  • Network access for the first run (toolchain and project tools are downloaded and checksum-verified).

You do not need to install Go, Node, Java or any other ecosystem toolchain to use Oyzu on a project. Oyzu acquires the tools a project asks for. See Manage your first tool.

Build it​

The checkout provides a bootstrap script that builds the CLI with the pinned toolchain, copies it to .oyzu/bin and installs the repository's own locked tools:

tooling/bootstrap-oyzu.sh
export PATH="$PWD/.oyzu/bin:$PATH"

If you already have a suitable Rust toolchain you can build directly:

cargo build --locked

The executable is then target/debug/oyzu (target\debug\oyzu.exe on Windows). Put its folder on your PATH, or call it by full path.

Check that it works​

$ oyzu --version
oyzu 0.1.0-local.564f462704df (debug; x86_64-pc-windows-msvc; build 1792551563)

The version string names the source revision and platform of this build; it is not a release label. Then:

$ oyzu --help
oyzu. 0.1.0-local.564f462704df (debug; x86_64-pc-windows-msvc; build 1792551563)
Opinionated native project tasks and builds
​
Usage: oyzu [OPTIONS] <COMMAND>
​
Develop & build:
  run          List tasks or run a development task
  build        Build native artifacts or use an isolated build
  publish      Publish finalized artifacts to configured destinations, or request governed publication
  lock         Write or check OS package locks for Docker targets
  cache        Inspect or clear the local action cache
  scan         Run the experimental policy-selected scan against recorded build inputs
  discover     Show the targets Oyzu detected here and which builder handles each
  inspect      Verify a build's output: its recorded files and digests (not who produced it)

Project tools:
  pin          Lock discovered tool requirements without installing
  install      Install configured tools, or declare, lock and install the named ones
  engine       Install a verified engine package for this user without changing PATH
  update       Move locked versions forward within each existing requirement; never edits configuration
  uninstall    Remove tool declarations and their lock entries; shared installations stay in the store
  reshim       Refresh installed-tool shims and existing activation launchers
  exec         Run a command in the frozen project environment
  which        Locate a verified command in the frozen tool selection
​
Environment & configuration:
  env          Inspect the available selected environment or print shell assignments
  config       Inspect, explain or edit project configuration
  trust        Allow this project's environment and PATH settings without prompting
  shell        Set up or remove shell integration
  activate     Print shell activation code
  deactivate   Print code to restore this shell session
​
Platform:
  auth         Sign in to the platform, check the local session or sign out
  release      Ask Oyzu about releases of this project's build
  secrets      Manage the platform account's secrets; values are write-only
​
Diagnostics:
  tools        Inspect tool records without executing tools
  plugins      Find plugins, see which one a project uses and why, and update locked selections
  history      List retained build invocations, or show a bounded summary by identity
​
Options:
  -C, --directory <DIRECTORY>  Run from this directory
      --json                   Return machine-readable results and errors
  -v, --verbose...             Show debug diagnostics; repeat for trace
  -q, --quiet...               Hide routine Oyzu progress, preserving results and child output
      --log-level <LOG_LEVEL>  Set the diagnostic threshold [possible values: error, warn, info, debug, trace]
      --root <ROOT>            Use an explicit project root
      --profile <PROFILE>      Select a configuration profile
      --no-profile             Disable profile selection
      --toolset <NAME>         Use a toolset's tools ([toolsets.NAME.tools] in oyzu.toml) for exec, run, env, activate, which, install, update, uninstall and pin

  -h, --help                   Print help

Examples:
  oyzu run                  List available tasks
  oyzu run test             Run the project's tests
  oyzu pin --dry-run        Preview required tool versions
  oyzu install go@1.26      Declare, lock and install a tool
  oyzu build --plan         Inspect the build plan
​
Use oyzu <command> --help for command options.

The help groups commands by job. The platform group (auth, release, secrets) needs an Oyzu platform account; everything else works without one. oyzu <command> --help works offline, with no project open.

Supported platforms​

Oyzu is built for Windows, macOS and Linux. Support differs by ecosystem and tool provider, and the project is early: see what works today and known limits before relying on a combination.

Install a verified local engine package​

If you already have a compatible development engine archive and its verified identity and digest, a CLI containing the installer command can install it for your user:

oyzu engine install --identity <BUILD_ID> --archive ./engine.tar.gz --sha256 sha256:<HEX>

Run the Executable path in the result. The installer does not change PATH or pin a project. That exact installed executable can supply its own captured workers without an engines.packages entry. Copying the executable elsewhere does not copy this authority. Explicit project pins and administrative pin requirements still take precedence. Use --json for the machine-readable installation record.

The engine staging reference describes package requirements, registration, offline use and refusal recovery.

Start a project​

Run it on a project: the tutorial builds a real program step by step, and Your first build is the short version. Something wrong? See troubleshooting.
