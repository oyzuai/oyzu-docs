Declared fetches

CLI reference

Published from the canonical docs/reference/declared-fetches.md file. Features marked experimental remain experimental; check support limitations before relying on them.

A declared fetch names one file by HTTPS URL and SHA-256 digest in build.yaml. Captured preparation downloads it, verifies it and delivers it to the build. The build itself then runs offline, so a RUN curl or a script download can be replaced with a pinned input.

Status: experimental. This first slice follows the draft declared fetches design; field names and messages may still change. It has unit tests but has not been qualified end to end yet (see verification).

Declare a fetch​

builds:
  image:
    uses: docker/image
    fetches:
      - name: migrate
        url: https://github.com/golang-migrate/migrate/releases/download/v4.18.1/migrate.linux-amd64.tar.gz
        sha256: <64 lowercase hex characters>
        unpack: tar
FieldRequiredMeaning
nameyesTarget-unique name: a letter, then up to 63 letters, digits, _ or -
urlyesAn https:// URL without user information, query or fragment
sha256yesExpected digest of the downloaded bytes, 64 lowercase hex characters
unpacknotar (plain or gzip, detected from the bytes) or zip. Without it the file is delivered as is

A target can declare at most 64 fetches. Two names that give the same environment variable, such as migrate-cli and migrate_cli, are refused. An invalid declaration fails with CONFIG_INVALID_VALUE when build.yaml is read, before any preparation.

Without unpack, the file keeps the last segment of its URL as its name. That segment may contain only letters, digits, ., _, + and -.

Use it in a build​

In a Dockerfile, copy from the named context oyzu-fetch-<name>:

COPY --from=oyzu-fetch-migrate migrate /usr/local/bin/migrate

The context holds the unpacked tree, or the single downloaded file. A Dockerfile that reads oyzu-fetch-<name> without a matching declaration fails during preparation. These context names are reserved and are never treated as images.

Command actions (prepare, task and package commands) get OYZU_FETCH_<NAME>, the name upper-cased with - replaced by _. It points to the file, such as /dependencies/fetches/migrate-cli/migrate, or to the unpacked directory, such as /dependencies/fetches/migrate. Content is read-only.

Declared fetches are delivered only on captured worker paths: oyzu build --isolated and builders whose host build runs a captured worker, such as Docker images. A native host build of a target with fetches fails and asks you to run oyzu build --isolated. A builder that captures no dependency inputs cannot receive fetches and fails with a message naming the target.

Sources​

Standalone, any HTTPS URL is admitted, and HTTPS redirects are followed. The broker forwards no credentials, and every hop must still be HTTPS.

An administrator can restrict fetches with fetches.sources, a list of HTTPS URL prefixes ending in / (see configuration). Then:

  • A URL outside every prefix fails with SOURCE_DENIED before anything is downloaded. The prefix is matched by path segment, so /tools/ does not admit /toolsets/.
  • Every redirect must stay inside the listed prefixes, or the fetch fails with REDIRECT_DENIED.
  • Project configuration cannot set fetches.sources, so a project cannot widen it. Setting it there fails with CONFIG_SCOPE.

Store and offline builds​

Verified bytes are stored by digest under <user data>/cache/fetches/sha256-<hex>. Bytes are checked before they are stored or unpacked. A mismatch stores nothing, and a damaged store entry is replaced rather than trusted.

A later build reuses the stored file without downloading. With --offline, a fetch that is not stored fails with DEPENDENCY_INPUT_MISSING. Run one online build to capture it.

Archives are unpacked with the tool store's defenses: path traversal, links that leave the tree and oversized expansion are refused.

Evidence​

Each fetch becomes a package in the target's dependency snapshot:

FieldValue
idfetch:<target>/<name>
version, digestsha256:<hex>
sourceIdfetch:<host> standalone, or fetches.sources/<index> under an allowlist
sizeDownloaded size in bytes
purposebuild
verificationdigest-only: the digest matched, but no publisher signature was checked

The snapshot extension oyzu.dev/fetches records each fetch's environment variable, path, context and tree digest. Both are part of the snapshot digest, so the plan and its evidence bind the fetched content. A second build of the same declaration records the same package identity.

Errors​

Each message starts with its code and names <target>: declared fetch <name>.

CodeCauseRecovery
CONFIG_INVALID_VALUEMissing digest, non-HTTPS URL, or a URL with user information, a query or a fragmentFix the declaration
INTEGRITY_MISMATCHThe downloaded bytes do not match sha256. The message shows both digestsCheck the URL and the upstream release before updating the digest. The observed digest has not been independently verified
SOURCE_DENIEDThe URL is outside fetches.sourcesUse an admitted source, or ask an administrator to admit it
REDIRECT_DENIEDA redirect left the admitted sourcesPin the final URL, or ask an administrator to admit its source
SOURCE_UNAVAILABLEThe server answered with a status other than 200Check the URL
DEPENDENCY_INPUT_MISSINGAn offline build needs a fetch that is not storedRun one online build

Limits​

  • Only SHA-256 digests are accepted. sha512 and Subresource Integrity strings and a helper that prints a URL's digest are open decisions in the design. Builder recipes for common downloads, such as Puppeteer's browsers, reuse this engine; see installer-asset recipes.
  • Credentialed sources are not supported.
  • Dockerfile ADD <url> with --checksum is still refused. Use a declared fetch and COPY --from=oyzu-fetch-<name>.
  • Native host builds do not receive fetches.
  • docker/image targets cannot build with --offline, because the Docker builder does not support offline preparation yet. Their fetches are still stored and reused by later online or --isolated builds without downloading again.
  • Only tar (plain or gzip) and zip can be unpacked.
  • An offline RUN curl still fails at execution. The failure does not yet suggest a declared fetch. A captured npm install whose lifecycle script tries the network does: see downloads without a recipe.

Verification​

Unit tests cover declaration validation, admission and the allowlist, digest mismatch with an empty store, offline reuse with the same package identity, tar unpacking, broker download and redirect denial, Docker named contexts and worker context capture. An integration test covers validation when build.yaml is read. These map to acceptance FETCH-02 to FETCH-05 and part of FETCH-01.

Not yet demonstrated: a Docker image built with oyzu build and with oyzu build --isolated that copies a fetched file, its evidence, and Windows and macOS behavior.
