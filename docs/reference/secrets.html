Platform secrets

CLI reference

Published from the canonical docs/reference/secrets.md file. Features marked experimental remain experimental; check support limitations before relying on them.

oyzu secrets manages the secrets your Oyzu platform account keeps for the account, one of its organizations or one of its projects. A secret is either a token a build job receives (build exposure) or a webhook secret the platform uses to check incoming deliveries (internal exposure).

Values are write-only. You can set or replace a value, but no command or API ever shows a stored value back to anyone, including account owners.

Note: This command is experimental and hasn't been tested against a live platform yet. Everything else Oyzu does is local and works without an account.

oyzu secrets create release-webhook --exposure internal --description "Release tool deliveries"
oyzu secrets set release-webhook --generate
oyzu secrets list

Prerequisites​

  • platform.url and platform.account in your configuration, usually at user scope: oyzu config set --global platform.account payments.
  • A platform credential: an oyzu auth login session (used at a terminal, or when platform.authentication.provider is session) or a token in OYZU_PLATFORM_TOKEN. See which credential a command uses. Unattended runs need an explicit provider or token and never use your stored session. Don't copy a browser session into a token.
  • Permission for the operation on the platform. Having a credential isn't enough on its own.

You don't need a Git checkout.

Commands​

CommandWhat it does
oyzu secrets listLists the account's secrets: name, type, exposure, value version and description.
oyzu secrets create <name> --exposure build|internalCreates a secret with no value. Add --type file for exact bytes such as a key file (default text) and --description.
oyzu secrets set <name> < value.txtSets or replaces the value from standard input.
oyzu secrets set <name> --file key.pemSets or replaces the value with a file's exact bytes.
oyzu secrets set <name> --generateGenerates a value, sets it and prints it once.
oyzu secrets set <name> ... --overlap 24hKeeps the replaced value valid for this long, up to 168h. Units: h, m, s.
oyzu secrets rm <name> --previousEnds an overlap now, for example if the old value leaked.
oyzu secrets rm <name>Deletes the secret and all its values.

Add --org <org> or --project <project> to any command to work in that scope; without them, commands act on the account. Use the organization's or project's identifier. set and rm accept a secret's name or id. set never creates a secret; if it doesn't exist you get SECRETS_NOT_FOUND with the create command to run.

Exposure, type and scope are fixed when you create a secret. To change one, create a new secret.

Rotate a webhook secret​

oyzu secrets set release-webhook --generate --overlap 24h
# update the sender with the new value
oyzu secrets rm release-webhook --previous

Both values are accepted during the overlap, so no deliveries are dropped.

Where a value comes from​

Values come from standard input, --file or --generate, never from a command-line argument, so they don't end up in shell history or process listings.

  • Standard input must be piped or redirected. If it's a terminal, set fails with SECRETS_VALUE_REQUIRED rather than echo what you type.
  • Bytes are sent exactly as read. echo token | oyzu secrets set x stores a trailing newline; use printf '%s' "$TOKEN" or a file without one.
  • A value can't be empty and can be at most 64 KiB. A text value must be UTF-8.
  • --generate takes 32 bytes from the operating system's secure random source and uses them as 64 lowercase hex characters, which webhook senders accept. The value is printed once, after the platform has stored it. If the platform refuses, the value is thrown away and never shown.

Output​

A listing is a table. The Value column shows the version (and, during an overlap, when the old one stops working) or not set:

Secrets · project web of payments

Name       Type  Exposure  Value                                                   Description
npm-token  text  build     version 2 (version 1 valid until 2026-10-11T09:05:00Z)
hook       text  internal  not set                                                 Release tool

Values are write-only: no command shows a stored value. Replace one with `oyzu secrets set <name>`.

A generated value is shown once:

✓ Set the value of release-webhook (version 1)

Generated value

  3f9c…(64 hexadecimal characters)

Copy it into the sender's webhook settings now. It cannot be shown again; if it is lost, set a new one.

With --json, standard output holds one record with kind, account and scope:

kindExtra fields
secretssecrets (metadata only)
secret-created, secret-overlap-endedsecret
secret-value-setsecret, and generated_value for --generate only
secret-deletedname, id

The JSON from --generate contains the value, so treat it as sensitive.

Errors and recovery​

Exit status is 0 on success and 2 on any failure. Platform errors keep the platform's code with a SECRETS_ prefix, plus the platform request id.

CodeCauseFix
SECRETS_NOT_CONFIGUREDplatform.url or platform.account is missing.Set them.
SECRETS_UNAUTHENTICATEDNo credential, or it was refused.Run oyzu auth login, or set a current OYZU_PLATFORM_TOKEN.
SECRETS_PERMISSION_DENIEDYou can't do this in that scope.Ask for access.
SECRETS_NOT_FOUNDNo secret with that name in that scope.Check the scope, or create it first.
SECRETS_RESOURCE_CONFLICTName already taken, no previous value to end, or a sign-only secret.Pick another name, or leave platform-managed secrets alone.
SECRETS_VALIDATION_FAILEDThe platform rejected a field (named in the error).Correct that field.
SECRETS_VALUE_REQUIRED, SECRETS_VALUE_EMPTY, SECRETS_VALUE_TOO_LARGE, SECRETS_VALUE_UNREADABLENo usable value.Pipe the value, use --file or --generate.
SECRETS_OVERLAP_INVALIDBad --overlap duration.Use a value like 24h, at most 168h.
SECRETS_UNREACHABLEThe platform couldn't be reached.Retry later.
SECRETS_RESPONSE_INVALIDThe platform's reply was malformed.Run oyzu secrets list to see what happened before retrying. Check CLI and platform compatibility.

list retries a 503 or network failure with backoff. create, set and rm are sent once, because retrying a value could create an extra version and, with an overlap, retire the value you meant to keep. If one fails in transit, run oyzu secrets list to check before trying again.

Security​

  • No command reads a value back.
  • Values never come from arguments, are never logged and are never written to disk by the CLI.
  • The credential is sent only to platform.url, using your proxy and trust settings. Redirects aren't followed.
  • A reply that contains a secret value is rejected, not printed.
  • sign-only secrets (the platform's own integration keys) are listed but can't be created or changed here.

Limitations​

  • There is no hidden prompt for typing a value. Pipe it or use --file.
