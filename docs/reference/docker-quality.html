Dockerfile linting and formatting

CLI reference

Published from the canonical docs/reference/docker-quality.md file. Features marked experimental remain experimental; check support limitations before relying on them.

Dockerfile projects get lint, a read-only format check and an explicit format task with no Oyzu configuration. Linting uses Hadolint 2.15.1 and formatting uses dockerfmt 0.5.4. Neither builds or runs your application.

Status: experimental. Managed defaults require a published tool pair for the execution platform; see Tools and platforms.

Platform scope: Use an x64 host and supported x64 build targets. ARM64 is unsupported. Feature-specific limits are listed in the support matrix.

Tasks​

oyzu run list
oyzu pin
oyzu run lint
oyzu run format-check
oyzu run format
oyzu build
TaskWhat it runsChanges files
linthadolint --no-color DockerfileNo
format-checkdockerfmt with --checkNo
formatdockerfmt with --writeYes. Only runs when you ask for it, and is not a build stage.
  • Hadolint's rules, severities, configuration and inline suppressions decide whether lint passes. It reads a target-local .hadolint.yaml or .hadolint.yml.
  • dockerfmt reads a target-local .editorconfig. With no .editorconfig, Oyzu adds --newline so formatted files keep a final newline. With one, dockerfmt's own defaults and your settings apply, including the end-of-file rule.
  • Oyzu does not parse these files itself. Invalid native configuration is a native failure.
  • Task listing needs neither checker. Before a selected task runs, Oyzu prepares its exact locked tools in the shared store. A missing pin or unavailable platform fails preparation; no checker is silently skipped.
  • Task overrides and pre/post hooks work as for other tasks. A task you replace owns its own behavior.

In a build​

In an isolated oyzu build, lint and format-check are required gates before the image archive is collected. If either fails, the diagnostics are kept and no image artifact is produced. Your source and checkout are unchanged. Fix the findings, run oyzu run format if you want the formatter to rewrite the file, and build again.

Lint results are not counted as application tests or coverage. The image's JUnit report comes from the OCI checks, and coverage is recorded as not applicable.

.dockerignore controls what goes into the image, not what the checkers see. Oyzu keeps .hadolint.yaml, .hadolint.yml and .editorconfig available to the checkers even if .dockerignore excludes them from COPY.

Configuration from folders above the target is not imported in a build. Keep required checker configuration inside the target folder so isolated and local runs agree. Local development runs also see configuration from your machine. Isolated builds do not mount any.

dockerfmt defaults to four-space continuation indentation. If your repository has an .editorconfig in a parent folder, copy a Dockerfile example elsewhere before comparing native defaults.

Tools and platforms​

oyzu pin records Hadolint and dockerfmt under quality.docker in oyzu.lock, with exact versions, upstream URLs, upstream integrity and SHA-256 values. The first quality task installs the pair in the shared tool store. Host tasks and isolated builds consume the same selection; neither checker needs to be on PATH or in a custom execution image.

Downloads use the normal source-admission rules and are verified before installation. Hadolint's upstream license and source pointers are retained, as are notices inside the unchanged dockerfmt archive. Installed payloads are trusted on reuse. Isolated actions restore a read-only archive and run with networking disabled on the base execution image.

The managed pair has upstream assets for Linux x86-64, Linux arm64 and macOS arm64. Hadolint also publishes other assets, but no complete managed pair is available for Windows or macOS x86-64 because dockerfmt does not publish matching binaries. Selecting either host fails with QUALITY_PLATFORM_UNAVAILABLE; a tool found on ambient PATH does not fill the gap. Use a supported Linux executor or an explicit project task with its own tools. Asset availability does not imply that every platform has been qualified through a full image build.

Ordinary runs, builds and oyzu pin retain the exact project lock. Use oyzu pin --refresh or a whole-project oyzu update to adopt the defaults shipped by your current CLI. The next task prepares the new selection. Offline checks need the lock and bundle already available in the same store. If fetches.sources is restricted, permit the locked GitHub release and license URLs; source restrictions apply on reuse too. See locked quality tools.

Limits​

  • Hadolint is a static linter. It is not a vulnerability scanner and does not prove policy compliance. Inline suppressions change its result.
  • dockerfmt has documented syntax limits, including escape directives and some shell grouping forms. See Hadolint and dockerfmt for their configuration.
