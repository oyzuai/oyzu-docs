Tool Helm Installation

CLI reference

Published from the canonical docs/reference/tool-helm-installation.md file. Features marked experimental remain experimental; check support limitations before relying on them.

Indexed installation and pinning use the organization catalog contract. A matching verified index record is preferred without a catalog; with one, only approved indexed releases install. The provider evidence command uses the same metadata adapter as installation. Linux ARM64 GNU joins the native host/lock matrix (Tailscale remains Linux-only); macOS amd64 and musl are excluded. See implementation status for automated verification. Live publisher evidence and native ARM64 qualification remain pending.

Oyzu can pin and install helm, so a project that packages or deploys Helm charts needs no host-installed copy. See tool management for shared prerequisites.

Usage​

[tools]
helm = "3.16.2"    # exact release
# helm = "latest"  # the publisher's current stable release
oyzu install helm@3.16.2   # declares, locks for every platform, installs this one
oyzu exec -- helm version --short
oyzu which helm

How versions are chosen​

Only an exact version (3.16.2 or v3.16.2) or latest is accepted. The Helm download host has no list of releases, so ranges, minor lines such as 3.16 and pre-releases are refused with a message naming the accepted forms, and oyzu tools versions helm fails for the same reason. latest reads the publisher's helm-latest-version marker, which currently names a 4.x release; pin an exact version when a project depends on 3.x behavior. The lock records the resolved version, so latest does not move until oyzu update.

Sources and verification​

Each release publishes one archive per platform on https://get.helm.sh/: a tar.gz for Linux and macOS and a zip for Windows, each containing a single <os>-<arch>/ directory with helm, LICENSE and README.md. Oyzu strips that directory, so helm (or helm.exe) is at the root of the installed payload. The digest for each platform comes from the archive's .sha256sum sidecar on the same host, which must name the requested archive; Oyzu locks it, downloads the archive through the tool broker and verifies the bytes before storing them. The digest comes from the publisher, not a signature. Oyzu does not redistribute the archive. Administrative tools routes scoped to helm, oyzu:helm or * use the same host connector bindings as the other tools; there is no public fallback from a configured route.

Supported platforms are linux/amd64/gnu, linux/arm64/gnu, darwin/arm64/native and windows/amd64/msvc. The installed command is helm.

Verification and limits​

Verified against the live publisher on two hosts. On Windows 11 x86_64, oyzu install helm@3.16.2 and helm@latest locked all three platforms and installed the Windows zip, oyzu exec -- helm version --short printed v3.16.2+g13654a5 and v4.3.0+gbec5b06, and a range request and tools versions were refused. On Linux x86_64 (Ubuntu 24.04 container), oyzu install helm@3.16.2 installed the tarball and helm version --short printed v3.16.2+g13654a5. For macOS the locked digest was checked against the downloaded archive and its listing (a single darwin-arm64/ directory containing helm), but that binary was not installed or executed, and no chart was packaged. Not covered: offline replay with a cold store.
