Ant builds and test reporting

CLI reference

Published from the canonical docs/reference/ant.md file. Features marked experimental remain experimental; check support limitations before relying on them.

The java/ant builder captures conventional/custom Ant projects and exports versioned JARs. Native oyzu run test is a separate host workflow that produces test and coverage evidence without packaging a JAR. These paths share the native Ant reporting integration; a direct-test pass does not qualify captured delivery.

Captured JAR builds​

oyzu build --isolated --full
oyzu inspect dist

Docker and the explicitly provisioned oyzu-toolchain/ant:1.10.18-jdk17 image are prerequisites. The image supplies Ant, JDK 17, JUnit 4.13.2, Hamcrest 1.3, JaCoCo 0.8.13 and Java quality tools. Rebuild it with the current compiled worker after launcher changes. There is no native host-build adapter; host direct tests do not remove the captured build's executor/image requirements.

--isolated selects captured execution; --full requests test and quality operations in addition to build/archive/package. Isolation alone does not request all checks. Plain local oyzu build retains the shared fast defaults; explicitly required checks still apply. Ant selects native archive targets and contained JAR paths from admitted metadata evaluation rather than inventing a project layout. Native arbitrary downloads and projects with ivy.xml are not supported captured dependency acquisition; Ivy is explicitly refused.

The bundle contains versioned JARs and current evidence for selected checks. Native failures or missing required reports block exported artifacts and retain available reports in the failed bundle. An opaque override that exits zero with optional reports absent remains incomplete reporting; a [checks] section with tests = "required" and coverage = "required" makes those reports mandatory (check levels). See direct reporting acceptance for the shared distinction between command success and verified evidence.

Direct tests​

Ant projects with a conventional test target can run oyzu run test to produce native test and coverage evidence in a test-only dist/ bundle. The direct adapter reuses the captured builder's Ant listener, JUnit formatter and JaCoCo integration. It does not create a new test framework or require an Oyzu configuration file for the conventional case.

oyzu run list
oyzu run test
oyzu inspect dist

For an existing custom target, a task replacement selects it:

[tasks.test]
argv = ["ant", "verify-contract"]

One literal ant <target> command is instrumented, including the equivalent literal shell spelling used in the custom example. Compound shell commands and arbitrary replacements retain their bodies and must produce the required JUnit and JaCoCo reports themselves, using the assigned OYZU_TEST_REPORT and OYZU_COVERAGE_REPORT paths. Extra forwarded arguments to the automatic adapter are currently unsupported and fail explicitly. Target-qualified names and pre/post hooks use the common task engine. A failed test skips its success-only post hook.

Discovery always supplies an implicit builder-owned test slot. A root [tasks.test] replacement in a single-target project selects a custom Ant target while retaining report obligations through the shared task owner resolution. Without a native test target or a replacement, execution fails with Ant's missing-target error; discovery does not fabricate a test suite.

Direct-test prerequisites​

Provision a JDK with java and javac, Ant and JaCoCo before execution. Set JAVA_HOME to the JDK or put both executables on PATH. Set ANT_HOME to the Ant distribution and JACOCO_HOME to a directory containing jacocoant.jar and jacocoagent.jar. JUnit projects also need their normal test libraries; the CI fixture puts JUnit and Hamcrest in Ant's lib directory. Native libraries are loaded from that directory. The adapter compiles its owned Java integration into a temporary directory and launches Ant using the host's classpath separator. It does not install tools or download dependencies.

The CI provisioner supplies checksum-pinned Ant 1.10.18, JaCoCo 0.8.13, JUnit 4.13.2 and Hamcrest 1.3:

python tooling/provision-ant-reporting.py --destination /absolute/path/ant-reporting
python tooling/test-ant-direct.py --cli /absolute/path/oyzu --tools /absolute/path/ant-reporting

The first command is explicit online test setup, outside product execution. The second additionally needs tooling/design-requirements.txt. CI uses JDK 17 and runs the probe after compiling the CLI on Windows, Linux and macOS; registration alone is not verified platform support.

Reports and native behavior​

The manifest links JUnit outcomes and JaCoCo application coverage. Native JUnit suites retain individual tests and skipped cases. Conventional forked Java assertion programs produce one case per invocation. These programs require fork="true" and failonerror="true". Coverage follows the existing adapter's conventional src ownership and observed javac output; test classes are excluded. Builds without line debug data retain the available instruction counters rather than inventing line coverage. Arbitrary source layouts, alternate task implementations and JUnit Platform integration require further work or explicit reports.

Direct tests keep native project version properties, execute the target's compilation prerequisites, and can update native build output. They do not package snapshot artifacts or run lint/format checks. oyzu build --isolated --full projects snapshot versions, requests quality gates and collects JAR artifacts. Both paths use the same native reporting implementation; captured execution retains its fixed tool locations and isolation.

Captured builds use shared version inference over the native version property and applicable Git history. Ant's model is queried again with the chosen version/oyzu.version user properties before planning. The versioned artifact name, bundle version and exported JAR Implementation-Version agree. Native qualifiers are preserved when they cannot participate in SemVer inference; exact tag intent still produces a snapshot without release authority.

Missing tools, compilation errors, native test failures, missing or invalid reports and unmet coverage constraints fail the command. Available current reports remain in the failed bundle; correct the native prerequisite or project and rerun. The shared collector owns report validation, hook ordering, bundle history and inspection. See direct test reports for existing-output preservation and host provenance. Host tasks can access the host network and ambient environment; these reports do not prove hermetic execution.

Verification​

tooling/test-ant-direct.py exercises the authored conventional/custom Ant examples and a native JUnit fixture through the compiled CLI: task discovery, real tests, current JUnit/JaCoCo, unchanged source/configuration, hooks, failed assertions and bundle inspection. tooling/test-ant-reporting.py separately checks the underlying native adapter. Current measured outcomes are recorded in implementation status; captured JAR acceptance and direct test acceptance are distinct.

The captured ant scenario uses the same fixtures and requests isolated/full execution. It checks native application-only coverage, versioned JAR manifests, delivered-JAR execution (including native JUnitCore), unchanged source and repeated plan/artifact identity. Native assertion, custom-target, JUnit and explicitly required-report failures must block artifacts. The normalized-flow qualification record owns its reproducible command, exact candidate/tool identities and current execution limits. The targeted Linux group passed conventional/custom/JUnit captured builds, independent delivered-JAR execution, required reports, repeatability, source preservation and failure gates. All three direct-test fixtures also passed. These bounded fixtures do not establish broader layouts, frameworks or additional platform support.

Both probes passed locally on Windows with JDK 17.0.20.1, Ant 1.10.18 and JaCoCo 0.8.13, using the pinned CI prerequisite bundle. The direct CLI step passed on Linux, macOS and Windows at 343c682 in run 37052623343 (jobs 110991301336, 110991301392 and 110991301544 respectively). The existing captured Java suite passed at 039f83a, before this shared-launcher change; the changed captured launcher still needs its CI regression run.

The compiled Oyzu worker owns process sequencing and native report composition. Native Java integrations remain embedded assets; Python is not required to execute these builder operations. Rebuild captured images after updating the worker.
