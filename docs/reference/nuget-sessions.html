Managed NuGet/.NET launch sessions (prototype)

CLI reference

Published from the canonical docs/reference/nuget-sessions.md file. Features marked experimental remain experimental; check support limitations before relying on them.

Oyzu can automatically prepare native dotnet restore and dotnet build with a session-scoped NuGet credential plugin. This is an opt-in client prototype with a simulated local agent in its proof. It is not the captured .NET oyzu build builder (see .NET builds, which does not use sessions yet), platform login, or CI identity implementation.

Setup and use​

Provision a .NET 8 SDK and configure an agent endpoint in user or administrative Oyzu configuration:

[nuget]
sessionEndpoint = "http://127.0.0.1:43199/session"

The port is illustrative. The existing configuration cascade resolves the setting. Project/local/invocation origins and profile selection cannot choose the endpoint. It must be numeric-loopback HTTP without credentials, query or fragment. The setting is absent by default; removing it restores standalone launch behavior. User configuration remains excluded in CI by existing rules.

oyzu exec -- /usr/share/dotnet/dotnet restore --locked-mode
oyzu exec -- /usr/share/dotnet/dotnet build --no-restore
# With provisioned dotnet on PATH:
eval "$(oyzu activate bash)"
dotnet build

Linux with the .NET 8 SDK is the measured platform. Native Windows/macOS execution is unqualified; Windows managed-session shell shims are not implemented. Only restore and build are supported managed operations. Native help/version/info and installed-SDK/runtime listing bypass session creation. Other operations fail explicitly rather than bypassing admission. In particular, dotnet nuget push is not offered; artifact publication belongs to oyzu publish. Native .NET publish also remains outside this bounded command surface, even though it normally prepares application output rather than uploading a package.

Session and native configuration​

Every supported launch asks the agent for admission before compiling its adapter or starting native project work. This includes build --no-restore with already restored packages. The request contains directory, tool and arguments; the local directory is a context hint, not verified source ownership.

The experimental response supplies feed, credentialScope, username and credentialEndpoint. Feed and scope must share an origin, the scope must end in /, and the feed must lie below that path. URLs must be credential-free HTTP(S) without query/fragment. The credential endpoint is numeric-loopback HTTP. The first adapter supports one feed and one same-origin credential scope; cross-origin service resources require separate qualification. A literal semicolon in the feed is rejected because NuGet interprets restore sources as a list.

Rust compiles Oyzu's bundled minimal C# plugin using the already selected SDK in a temporary directory, with package sources cleared for that compilation. No third-party package or extra language runtime is required. It stages a temporary credential-free NuGet config and session metadata and selects the plugin using NUGET_NETCORE_PLUGIN_PATHS. NuGet starts the plugin and requests credentials over its native process protocol. The plugin obtains the password from the admitted session only for a URI inside the allowed scope.

Managed mode replaces restore configuration/sources through MSBuild global properties, clears additional project restore sources, replaces native plugin-path selection, and removes the environment credential override for the managed source name. The fixture explicitly includes a conflicting project RestoreSources property to verify the approved feed wins. Project files are not edited. Other native project build settings stay native-owned, but this prototype does not merge custom source mappings, multiple feeds, custom settings files or provider plugins. Explicit source/config overrides on the command line are rejected.

Passwords travel through native process memory and NuGet plugin pipes, never through the generated settings, launcher arguments or launcher environment. The session locator is access-sensitive; the laboratory transport is not a production authenticated IPC channel. Native build code can access process state; this is not hostile-code containment. Upstream identity permissions enforce read-only access.

Output, effects and limits​

Native output and exit status follow oyzu exec; global --json retains captured native streams in its structured result. The launcher disables MSBuild node reuse for the child. Normal native package/HTTP caches remain enabled. Temporary plugin source, build output, settings and metadata are removed after normal success or failure. Project outputs, lock files and native caches remain native-owned. Abrupt parent termination cleanup and compilation caching are deferred.

NATIVE_SESSION_* errors identify shared authority/admission failures. NUGET_SESSION_INVALID identifies malformed feed/session data; NUGET_SESSION_PREPARE requires a working .NET 8 SDK and local reference packs; NUGET_ROUTING_CONFLICT rejects competing source/config arguments; NUGET_OPERATION_UNSUPPORTED identifies a command outside restore/build. Agent outage/denial fails before native work, with no direct fallback or offline grant. Plugin failures return generic errors rather than upstream response bodies.

Argument checks are a bounded supported surface, not a complete MSBuild parser. Arbitrary project targets/network calls, inherited custom MSBuild behavior and additional SDK/runtime versions are not qualified. Production platform and CI identity integration are deferred. No Oyzu schema version changes; NuGet's plugin protocol version belongs to NuGet.
