Mocha tests and coverage

CLI reference

Published from the canonical docs/reference/mocha.md file. Features marked experimental remain experimental; check support limitations before relying on them.

The Node builder runs your Mocha tests with your own Mocha setup and collects a JUnit test report and an LCOV coverage report from them. Use it when your package already tests with Mocha and you want those reports in the build output.

Note: This integration is experimental.

Quick start​

For a package that tests with npm and Mocha, add Mocha and c8 as dev dependencies and keep a plain mocha test script:

{
  "scripts": {"test": "mocha"},
  "devDependencies": {"mocha": "12.0.3", "c8": "10.1.3"}
}

Install dependencies with npm, then run the tests:

oyzu run test
oyzu build app --full --offline

The test run writes junit.xml and coverage.lcov into the build's reports/ folder (see Reports). No Oyzu test or report section is needed in your configuration.

How Mocha is detected​

The builder detects Mocha from, strongest first:

  1. A test script that runs mocha, including a compound script that names only Mocha.
  2. A native .mocharc file or a mocha section in package.json.
  3. A mocha dependency.

Oyzu reads configuration files without running them. If two frameworks have equally strong evidence, selection fails and names the with: {test-framework: <name>} selector in build.yaml. See discovery selectors.

With no test script, a detected Mocha project gets an implicit test task that runs node node_modules/mocha/bin/mocha.js. oyzu run list shows it and oyzu run test runs it. Direct tests in single packages and npm workspaces also collect JUnit and LCOV into a test-only dist/ bundle. See direct tests and workspace test bundles.

Supported setups​

SetupMochac8
Single npm package, implicit tests and host oyzu build12.0.310.1.3 in your project
Scripted direct tests, isolated builds and npm workspaces11 (tried with 11.8.0) or 12.0.310.x or 12.x in your project, or Oyzu's locked default c8

The single-package setup is supported on Linux and Windows (x86-64). For the platforms of isolated builds, see local builds. Other Mocha versions, pnpm and Yarn projects, and macOS are not supported yet.

Single npm package: implicit tests and host builds​

This setup requires exactly mocha 12.0.3 and c8 10.1.3 in dependencies or devDependencies.

  • It adapts an implicit Mocha test or a script that is exactly mocha, and keeps npm's script lifecycle and your configured Mocha reporter and options.
  • Exact task overrides sh -c 'mocha' and sh -c 'npm run test', and their PowerShell equivalents, use the same reporting adapter. Oyzu normalizes these recognized bodies before adding reporter flags; npm run test keeps npm's script lifecycle. Other shell bodies run as authored.
  • Tests run serially. Watch mode and parallel mode are not supported.
  • You cannot override the CLI reporter, and Oyzu rejects authored c8 configuration (.c8rc.json and similar). c8 reports the sources your tests load, not every file in the repository. An authored c8 configuration fails with a message directing you to an authored test task with explicit reports. This rejection happens before tests run, so no JUnit report is expected; a missing-report manifest record has no file path. Keep required coverage minimums in that authored task rather than removing them to enable automatic reporting.
  • Oyzu never downloads a reporting tool. The c8 in your project is always used.
  • oyzu build app --full --offline uses your existing npm lock and cache and fails if a required input is not cached. Without --offline it prepares dependencies as usual.

Scripted direct tests, isolated builds and npm workspaces​

Keep your existing project and native configuration:

{
  "scripts": {"test": "mocha"},
  "devDependencies": {"mocha": "11.8.0"}
}
  • Mocha must be a declared dependency that is captured with the build.
  • c8 10.x or 12.x in your project is used when present. A declared but missing c8 fails. Without any c8 dependency, the locked Node quality set supplies the fallback. Run oyzu pin before a direct task; task preparation installs the selected set in the shared store. See Node quality for refresh and offline behavior.
  • The test command runs under c8. Native thresholds, include and exclude rules and source-map handling in your c8 configuration apply. Only LCOV is exported, so additional coverage formats are not.
  • No build action downloads reporting tools.

Reports and failure gates​

The engine collects the reports under dist/<target>/<platform>/reports/ and records their paths, digests and summaries in the manifest.

ReportFile
Test results (JUnit, from Mocha's XUnit reporter)junit.xml
Coverage (LCOV, from c8)coverage.lcov

Native suite and workspace report allocations include the suite's identity in their filenames, so members can share native report basenames. Read the bundle manifest for collected paths; see workspace test bundles.

The adapter combines your configured Mocha reporter with Mocha's XUnit reporter, so your reporter options keep working.

Oyzu supplies the reporting adapter itself; you do not need to copy a reporter into your project. The selected Node plugin stages the embedded mocha-native-reporter.cjs in its private runtime directory for the run, both for host tests and inside isolated builds.

  • A failed assertion keeps the reports that exist and blocks packaging.
  • A failed coverage threshold fails the build even when every test passed.
  • Passing coverage never turns a failed test into a success.
  • A configuration or startup failure never reuses an earlier run's reports.
  • A command that exits zero without writing a required report fails the required-report gate.

Read the action log to see why a report is missing, fix the cause and rerun. A successful build also produces the normal Node package artifact.

Build, test, lint and read-only formatting stay separate stages. The default lint rules know Mocha globals in conventional test folders and in test and spec files. Your own lint configuration takes precedence. See Node lint and formatting.

npm workspaces​

Workspaces use the same adapter. Each member resolves Mocha, its configuration and c8 from its own folder, including hoisted installs.

  • A publishable root without a test script gets its own test suite. It excludes workspace members and Oyzu's own state with Mocha's --ignore option, and keeps your existing exclusions. Its planned argv stays bound to the selected workspace command; native execution runs that root suite with Mocha, not another recursive workspace invocation.
  • An explicit script keeps its native file selection, including --file entries, which Mocha does not filter through --ignore.
  • An explicit root test script produces one combined report pair. Otherwise each package gets its own JUnit and LCOV files, and a failure in one package keeps its siblings' results and blocks packaging.

See npm workspaces.

Limits​

  • Isolated builds recognize a bare mocha, its direct Node entry point and equivalent exact task overrides. Other shell commands, and scripts with extra flags, run as written. They must write their own required reports, and Oyzu does not guess a rewrite. Configure recognized runs through your Mocha configuration.
  • Watch mode is turned off. Parallel Mocha reporting is not supported and fails when Oyzu detects it.
  • Browser runners and custom reporters are not supported.
  • Mocha configuration is project code. Development tasks run it on your machine, and isolated builds run it in an offline sandbox. The reporting adapter gets no credentials and no network access.
  • A passing report shows the tests ran. It does not make a build eligible for release.
