The github: backend

CLI reference

Published from the canonical docs/reference/tool-github.md file. Features marked experimental remain experimental; check support limitations before relying on them.

github:<owner>/<repo> installs a program from a GitHub repository's release assets. It uses the same [tools] syntax as mise's github: backend. No account and no mise executable are needed.

Note: Experimental. Tested on Intel macOS with Pandoc 3.12.1 and Poedit GettextTools 1.0. Linux, Windows and Apple Silicon are not supported yet.

$ oyzu install github:cli/cli@2.49.2
$ cat oyzu.toml
[tools]
"github:cli/cli" = "2.49.2"

You need network access to api.github.com, github.com and GitHub's release-asset host. The lock covers every platform your builds declare, plus the current host. Use tools.lockPlatforms to lock other platforms (the host is always kept).

How a release is chosen and pinned​

  1. An exact MAJOR.MINOR.PATCH request reads the release tagged v<version> or <version>. latest and prefixes such as 2.49 pick the highest stable matching release. oyzu tools versions github:owner/repo lists them.
  2. For each platform, Oyzu picks the asset whose name best matches the OS, architecture and libc. A wrong architecture is never used as a fallback. Checksums, signatures, packages (.deb, .rpm, .msi) and source archives are never picked.
  3. The SHA-256 is the digest GitHub reports for the asset, or one from a checksum file published next to it. Oyzu downloads the asset once per platform, checks it against that digest and finds the command: the file named after the repository, or else the only executable.
  4. The lock records the asset URL, its SHA-256 and the command path. oyzu install --frozen doesn't need the GitHub API again.

Only the publisher's SHA-256 is checked. Attestations, signatures and SLSA provenance are not verified.

Pinned GNU gettext helper​

github:poedit/gettext-tools version 1.0 installs the GNU msgfmt from Poedit's GettextTools.xcframework.zip on macOS (11.5 or newer). Oyzu runs Versions/A/Helpers/msgfmt from the unmodified framework, so its bundled libraries load without extra settings. The package version (1.0) is separate from the gettext version the binary prints.

[tools]
lockPlatforms = ["darwin/amd64/native"]
"github:poedit/gettext-tools" = "1.0"

Oyzu only uses this command path for that exact archive (SHA-256 04dcba5b92ad8d0ff475e29baee72180f096431af220a858f0d29a9ec8988dcd). Other packages use the normal command detection, which refuses archives with more than one candidate.

Errors​

CodeCause and fix
TOOL_RATE_LIMITEDGitHub refused the request (anonymous rate limit or access policy). Set GITHUB_TOKEN; it is sent to api.github.com only.
TOOL_VERSION_NOT_FOUNDNo release matches the request.
TOOL_CHECKSUM_MISSINGThe release publishes no SHA-256 for the chosen asset. Nothing is installed.
TOOL_CHECKSUM_MISMATCHThe download doesn't match the published digest.
TOOL_ARCHIVE_UNSUPPORTEDThe chosen asset isn't tar.gz or zip (for example a bare binary or tar.xz).
TOOL_RECIPE_UNSUPPORTEDThe archive has no single identifiable command.
TOOL_SPEC_INVALIDThe ID isn't github:<owner>/<repo>.

Limitations​

  • Supported on Intel macOS only.
  • Not supported: bare-binary assets, tar.xz and tar.zst, options such as asset_pattern, bin and version_prefix, private repositories and GitHub Enterprise hosts.
  • tools versions lists releases without looking at their assets, so a listed version may have no build for your platform.
  • Resolving downloads each platform's asset once, which can be large.
