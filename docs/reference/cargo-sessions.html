Private Cargo registries

CLI reference

Published from the canonical docs/reference/cargo-sessions.md file. Features marked experimental remain experimental; check support limitations before relying on them.

Use this when your crates come from a private sparse Cargo registry and you want Cargo to get its token without cargo login or a credentials file. Each time you run Cargo through oyzu, oyzu asks a local credential agent for a session and hands Cargo the token in memory through Cargo's own credential-provider protocol.

Note: Experimental. You need a credential agent running on the same machine; oyzu doesn't include one. Supported on Linux with Bash (Cargo 1.95). Isolated oyzu build runs don't use this yet.

Configure​

Add the agent's address to your user or administrator configuration (not the project's oyzu.toml):

[cargo]
sessionEndpoint = "http://127.0.0.1:43199/session"
SettingValuesDefaultMeaning
cargo.sessionEndpointhttp://127.0.0.1:<port>/<path>, no user name, password, query or fragmentNot setThe local agent to ask for sessions. Remove it to go back to plain Cargo

Project, local and command-line configuration and profiles can't set this value. User configuration isn't read in CI, so this doesn't work there.

In your project, depend on the registry by name as usual:

[dependencies]
example = { version = "=0.1.0", registry = "internal" }

Run Cargo​

Run Cargo through oyzu exec, or in an activated shell:

oyzu exec -- /absolute/path/to/cargo build --locked
eval "$(oyzu activate bash)"
cargo fetch --locked

Supported commands are build, check, test, fetch and generate-lockfile. --help and --version run without asking the agent.

What oyzu does for you​

  1. Sends the agent a POST with {"directory": "<working dir>", "tool": "cargo", "arguments": [...]}.

  2. Reads the agent's answer:

    {
      "credentialEndpoint": "http://127.0.0.1:43199/credential",
      "name": "internal",
      "index": "sparse+https://packages.example.com/index/"
    }

    name uses lowercase letters, digits, _ or - and can't be crates-io. index is sparse+ followed by an HTTP(S) URL ending in /, with no credentials, query or fragment. credentialEndpoint must also be on 127.0.0.1.

  3. Starts Cargo with CARGO_REGISTRIES_<NAME>_INDEX and CARGO_REGISTRIES_<NAME>_CREDENTIAL_PROVIDER set for that registry, and CARGO_REGISTRIES_<NAME>_TOKEN removed. The provider is oyzu itself, run as cargo-credential-oyzu.

  4. When Cargo asks for a token, oyzu accepts only a read request for that exact index. It POSTs {"ecosystem": "cargo", "request": <Cargo's request>} to credentialEndpoint, which must answer {"token": "..."}.

Cargo may reuse the token for the rest of that one Cargo run, but not for other operations. Your CARGO_HOME, caches, Cargo.toml, Cargo.lock and other Cargo configuration are left alone. Any provider you've configured for the same registry is overridden for that run only.

The agent is asked every time, even for a warm offline build. Requests to the agent time out after 10 seconds and don't go through a proxy.

Credentials and security​

  • The token never goes into a file, a command argument or an environment variable. It's in Cargo's memory, so anything with access to that process (for example an administrator) can read it.
  • Read-only access has to be enforced by the registry account the agent uses.
  • If the agent fails, Cargo gets a generic error; the agent's response isn't shown.
  • Denial or an unreachable agent stops the command. oyzu never falls back to running Cargo without a session.

Output​

Cargo's output and exit code pass through unchanged. With --json, they're captured in the usual oyzu exec result.

Errors​

CodeCauseFix
NATIVE_SESSION_CONFIGThe endpoint is set in project or local configurationMove it to user or administrator configuration
NATIVE_SESSION_UNAVAILABLEThe agent can't be reachedStart the agent and retry
NATIVE_SESSION_DENIEDThe agent refused the requestGet access granted; don't work around the agent
NATIVE_SESSION_INVALIDThe endpoint isn't 127.0.0.1 HTTP, or the agent's response is too large or malformedFix the endpoint or the agent
CARGO_SESSION_INVALIDThe registry name or index in the response isn't validFix the agent's response
CARGO_OPERATION_UNSUPPORTEDThe Cargo command isn't one of the supported ones. cargo publish isn't supportedUse a supported command. Publish with oyzu publish
CARGO_ROUTING_CONFLICTYou passed --config, --token, --registry, --manifest-path, -C or --Remove the override

Limits​

  • One named registry per run. Other registries, Git and path dependencies, crates.io replacement, source replacement and Cargo aliases aren't covered.
  • Arguments after -- aren't supported.
  • Linux and Bash only. Windows, macOS and other shells aren't supported yet.
