Platform sign-in

CLI reference

Published from the canonical docs/reference/auth.md file. Features marked experimental remain experimental; check support limitations before relying on them.

oyzu auth signs you in to an Oyzu platform account and keeps the session in your operating system's credential store. Remote builds and runs (--remote), oyzu secrets and oyzu release check then use it. Everything else Oyzu does is local and needs no account.

Note: Platform sign-in is experimental. It needs a platform that publishes the sign-in endpoints described below; until it does, login reports discovery as unsupported. It hasn't been tested yet against a real identity provider or each operating system's credential store.

oyzu config set --global platform.url https://platform.example.com
oyzu config set --global platform.account payments
oyzu auth login
oyzu auth status

Commands​

CommandWhat it does
oyzu auth loginShows a web address and a short code. Approve the code in any browser, on any device. Oyzu then checks that you're an active member of platform.account and stores the session.
oyzu auth statusShows the platform, account and local session state: absent, active, refreshing, reauthentication-required or logged-out. Reads local state only; contacts no server.
oyzu auth logoutDeletes this account's local session, then asks the issuer to revoke it and reports that result separately.
oyzu auth conformanceChecks the client against a built-in fake issuer on your machine. Needs no account. Exits 1 if any scenario fails.

Prerequisites​

  • platform.url and platform.account set in user, machine or administrator configuration. Project and local files can't set them, so a checkout can't choose where your credentials go.
  • For login, a terminal where you can read the code.
  • A credential store: macOS Keychain, Windows Credential Manager, or a running Linux Secret Service provider (GNOME Keyring, KWallet). There is no plaintext fallback. Without a store, login stops before asking you to approve anything.
  • A platform that publishes OAuth protected-resource metadata (RFC 9728) naming one issuer that supports the device authorization grant (RFC 8628) for the public client oyzu-cli.

How login works​

  1. Oyzu reads /.well-known/oauth-protected-resource from platform.url (with the URL's path appended, if it has one). Its resource must equal platform.url, and it must list exactly one authorization server.
  2. Oyzu reads the issuer's metadata. The issuer must match, and its device and token endpoints (and revocation endpoint, if any) must use HTTPS on the issuer's own origin, with no credentials, query or fragment. Plain HTTP is accepted only for a loopback host. Redirects aren't followed and no token is sent.
  3. Oyzu starts the device grant for oyzu-cli, with no client secret and no scope (it never asks for offline_access). A verification address on a different origin isn't shown. Oyzu polls at the issuer's interval for up to 15 minutes.
  4. Oyzu calls GET /api/v1/access-context?account=<platform.account>. The answer must show an active membership of exactly that account; another membership is never used instead. If the account requires stronger sign-in, you get AUTH_STEP_UP_REQUIRED; without a membership, AUTH_NOT_A_MEMBER. In both cases the new sign-in is revoked and nothing is stored.

The session is stored only after every step succeeds, so a cancelled, denied, expired or failed login leaves nothing behind. The device code is never shown or logged.

Which credential a command uses​

Every command that talks to the platform gets its credential the same way. The rule is fixed, and a failure never falls back to a different identity.

SituationCredential
platform.authentication.provider is environmentOYZU_PLATFORM_TOKEN. Without it: AUTH_PROVIDER_UNAVAILABLE.
platform.authentication.provider is sessionThe stored session. If OYZU_PLATFORM_TOKEN is also set: AUTH_PROVIDER_CONFLICT.
platform.authentication.provider is networkNo Authorization header. The server identifies the caller through its trusted network. A supplied OYZU_PLATFORM_TOKEN is ignored.
platform.authentication.provider is workloadA fresh GitHub Actions OIDC token for every request attempt. A supplied OYZU_PLATFORM_TOKEN is ignored. Outside Actions: AUTH_PROVIDER_UNAVAILABLE.
platform.authentication.provider is private-key or executionAUTH_PROVIDER_UNSUPPORTED (not available).
No provider set, OYZU_PLATFORM_TOKEN setThat token, as given. It's never stored, refreshed or replaced.
No provider set, at a terminal (stdin and stderr)The stored session.
No provider set, unattended (CI, scripts, agents)AUTH_PROVIDER_REQUIRED. A stored session is never used implicitly.

If the platform rejects a token, the command reports *_UNAUTHENTICATED; it doesn't try your stored session instead. The credential is sent only to the origin of platform.url, never to a redirect or any other address.

Settings​

SettingValuesDefaultMeaning
platform.authentication.providersession, environment, network, workload (private-key, execution are reserved)unsetChooses the credential source, as above. Environment variable OYZU_PLATFORM_AUTH_PROVIDER. User, machine or administrator configuration only.

OYZU_PLATFORM_TOKEN holds a credential. It isn't a setting and doesn't belong in a configuration file.

Standalone pool credentials​

Use network only with a server that authenticates its callers through the network, such as a pool behind a trusted tailnet proxy. platform.url still requires HTTPS or loopback HTTP. The client never adds an identity header.

workload requires GITHUB_ACTIONS=true and a job with id-token: write. The client requests a token from ACTIONS_ID_TOKEN_REQUEST_URL, using ACTIONS_ID_TOKEN_REQUEST_TOKEN only at that endpoint. The audience is platform.url with trailing slashes removed, including any path prefix. The endpoint must use HTTPS or loopback HTTP, without user information or a fragment. Redirects are refused. Neither request secrets nor returned tokens are stored; each API attempt, including retries and cancellation, requests anew. See Actions usage.

These providers don't create a login session; auth status and auth logout still describe the stored session. They cannot authenticate a separate service host through the catalog administration client. Workload runs require network access to both the Actions token endpoint and the configured pool.

Storage, renewal and logout​

  • The refresh credential and the cached access token are stored as separate entries in the credential store. A small non-secret file under the user data directory (auth/) records the issuer, subject, state and expiry.
  • When several commands need to renew at once, only one renews; the others wait and reuse the result.
  • If a renewal answer is lost (timeout, crash, failed store write), the session ends with AUTH_REFRESH_AMBIGUOUS or AUTH_STORE_FAILED and you sign in again. A rejected renewal ends it with AUTH_REAUTHENTICATION_REQUIRED. An issuer outage or lost network leaves the session as it is.
  • logout wins over a renewal already in progress, which can't bring the session back.
  • Local logout can succeed while remote revocation can't. The result says so with remote: refused, unreachable or not-advertised. Access tokens already issued stay valid until they expire. A separately supplied OYZU_PLATFORM_TOKEN isn't affected.

Output​

Human output leads with the outcome. With --json, each command prints one record (auth-login, auth-status, auth-logout or auth-conformance) with session facts only. The login address and code go to standard error, and only when it's a terminal, so JSON on standard output stays clean. Without a terminal, login fails with AUTH_INTERACTION_REQUIRED before contacting anything.

Errors and recovery​

Failures exit 1. If a session can't be renewed, run oyzu auth login again.

CodeCauseFix
AUTH_NOT_CONFIGUREDplatform.url or platform.account is missing.Set them with oyzu config set --global.
AUTH_INTERACTION_REQUIREDlogin isn't running at a terminal.Run it in a terminal.
AUTH_STORE_UNAVAILABLE, AUTH_STORE_FAILEDThe credential store is missing, locked or failed.Start or unlock the store.
AUTH_DISCOVERY_UNSUPPORTED, AUTH_DISCOVERY_UNAVAILABLE, AUTH_DISCOVERY_INVALID, AUTH_DISCOVERY_AMBIGUOUSThe platform's sign-in metadata is missing, unreachable, invalid or lists more than one issuer.Check platform.url; ask your platform administrator.
AUTH_ISSUER_MISMATCH, AUTH_ISSUER_UNTRUSTED, AUTH_ISSUER_CHANGED, AUTH_REDIRECT_REFUSED, AUTH_GRANT_UNSUPPORTED, AUTH_DEVICE_UNTRUSTEDThe issuer's metadata or endpoints failed a safety check.Ask your platform administrator.
AUTH_DEVICE_EXPIRED, AUTH_LOGIN_DENIED, AUTH_LOGIN_CANCELLEDThe code expired, was denied or you cancelled.Run oyzu auth login again.
AUTH_NOT_A_MEMBER, AUTH_STEP_UP_REQUIREDYou aren't an active member of the account, or it needs stronger sign-in.Check the account, or complete the stronger sign-in.
AUTH_CONTEXT_UNAVAILABLE, AUTH_ISSUER_UNREACHABLEThe platform or issuer couldn't be reached.Retry later.
AUTH_LOGIN_REQUIRED, AUTH_REAUTHENTICATION_REQUIRED, AUTH_REFRESH_AMBIGUOUSNo usable session.Run oyzu auth login.
AUTH_DESTINATION_MISMATCH, AUTH_AUDIENCE_UNSUPPORTEDA credential would have gone to the wrong place.Check platform.url.
AUTH_PROVIDER_*See which credential a command uses.Set the provider or token.
AUTH_WORKLOAD_ENDPOINT_INVALIDUnsafe Actions token endpoint.Use the endpoint supplied by GitHub Actions over HTTPS.
AUTH_WORKLOAD_UNAVAILABLE, AUTH_WORKLOAD_REJECTED, AUTH_WORKLOAD_RESPONSE_INVALIDActions token request failed, was refused or returned an invalid response.Check id-token: write and endpoint connectivity; no other credential is tried.

Security​

  • Tokens, device codes and refresh credentials never appear in output, logs, configuration, command arguments, error text or the metadata file.
  • There is no plaintext credential file.
  • Coding agents and unattended jobs don't inherit your session. Don't give an agent your OYZU_PLATFORM_TOKEN: a copied token still identifies you.

Limits​

  • Supported credential stores are macOS Keychain, Windows Credential Manager and the Linux Secret Service, but none has been tested with real sign-ins yet.
  • Workload identity supports GitHub Actions only. The private-key and execution providers, browser-redirect (PKCE) login and a background agent aren't available. To switch accounts, change platform.account and run login again.
