Complete OCI image indices

CLI reference

Published from the canonical docs/reference/oci-indices.md file. Features marked experimental remain experimental; check support limitations before relying on them.

When a docker/image build lists several platforms, Oyzu builds one image per platform and also writes a single OCI index that points at all of them. No extra setting is needed. Use the index to publish or load a multi-architecture image under one reference.

Note: Image builds are experimental. The image builder produces linux/x86_64 and linux/arm64 images.

Example​

# build.yaml
builds:
  image:
    uses: docker/image
    platforms: [linux/x86_64, linux/arm64]
oyzu build image --plan
oyzu build image
oyzu inspect dist

The Dockerfile in this example contains FROM scratch and COPY. A Dockerfile with RUN still needs a worker that matches the platform it builds. See Docker image inputs for how to set up the Docker toolchain and BuildKit worker.

oyzu run list still shows only the builder's tasks. The index is made by an extra assemble-index step in the build plan, which appears after the per-platform image steps. oyzu build --plan shows the declared platform variants. The index step itself appears once the build is prepared.

When an index is made​

An index needs at least two platform variants of one target, all selected for the build, with image outputs that share one output name and version.

  • Each other variant axis forms its own group. Two runtime versions, for example, each get their own complete index.
  • A target with one platform just keeps its image.
  • If you select only some platforms of a larger family, Oyzu does not build a partial index. See matrix selection.

Outputs​

Each index produces:

  • An artifact of kind: "oci-index" with media type application/vnd.oci.image.index.v1+json.
  • A file at dist/<index-id>/any/<family>-<version>.oci.tar. It sits under any because it spans several platforms (see the bundle layout).
  • A file digest and size, plus ociDigest, the digest of the root index.

Read target IDs and paths from the plan or manifest instead of building the names yourself. The index target uses builder oyzu/oci-index and has platform: null. Null means a collection of platforms, not an artifact without a platform. Tools that read the plan or manifest must handle such targets. Ordinary image targets always have a concrete platform.

How the index is assembled​

Every per-platform image must build successfully first. Oyzu then checks each image archive's hash, size, OCI contents, digest and platform. It writes one archive that holds the unchanged image manifests, configs and layers (shared blobs stored once) and a sorted index. The same inputs always produce the same archive.

Assembly runs inside the CLI, reads the archives without extracting them and uses no network. It allows up to 256 input images and a 10 GiB archive. It does not run in a container, so it has no separate CPU, memory or time limits.

In the plan, this step is identified by extensions["oyzu.dev/oci-index"] and does not carry an executor mode. Execution handles it as in-process assembly; the platform image actions retain their own executor modes and worker checks.

If one platform fails, the index is not built, but the other platforms' images remain available to inspect. An index never leaves out a failed platform. Fix the failure and build again.

oyzu inspect dist checks that the index lists exactly the required images from successful builds. It rejects a complete-looking index that is missing a platform, and a bundle that is missing a planned index. Inspecting only the .oci.tar file checks its own contents but cannot tell whether the platform set was the required one. Neither check says who built it.

Limits​

  • Supported platforms are linux/x86_64 and linux/arm64. Images with RUN for a foreign platform are not supported.
  • Oyzu does not push an index to a registry. Publishing pushes single-platform images only.
  • ABI and CPU feature negotiation are not supported.

The archive follows the OCI image index specification.
