Node workspace test bundles

CLI reference

Published from the canonical docs/reference/node-workspace-tests.md file. Features marked experimental remain experimental; check support limitations before relying on them.

oyzu run test runs the tests of an npm, pnpm 10 or Yarn Classic workspace and collects each package's JUnit and LCOV reports into a test-only dist/ bundle. Your package manager decides workspace membership. Oyzu picks each package's test runner and collects the reports. No build YAML or reporting section is needed.

Note: Workspace test bundles are experimental. They hold results from your machine, not the versioned artifacts of an isolated build.

oyzu run list
oyzu run test
oyzu inspect dist

Prerequisites​

Install the project's dependencies and provide Node and your package manager first. Oyzu does not install tools or dependencies during this operation.

ManagerVersion tested
npm11.11.0
pnpm10.11.0
Yarn Classic1.22.22

Node 22 and 24 were used. pnpm and Yarn must expose their JavaScript entry point on PATH through a normal package install or native executable link. This works with package-local .bin directories and ordinary global installs on Windows and Unix. Corepack and standalone bundled pnpm executables are not used. A missing prerequisite or an unsupported manager major version fails with a message.

How workspaces are found​

oyzu run list reads native markers and scripts without running a package manager.

  • workspaces in package.json marks an npm or Yarn workspace.
  • pnpm-workspace.yaml marks a pnpm workspace, even before a lock exists.
  • Lockfiles and packageManager declarations take part in the normal manager conflict rules.

Actual membership is read only when you run tests. npm uses its installed dependency graph, pnpm uses its recursive JSON list (pnpm list), and Yarn Classic uses its workspace info output (yarn workspaces). Oyzu has no workspace glob parser of its own.

pnpm runs with automatic manager-version management turned off. Yarn runs in offline mode and ignores yarn-path. Your other project settings still apply.

How tests run​

Without a root test script, oyzu run list shows the manager's recursive test command. When you run tests, Oyzu reads membership, fixes each package's scope and report files, then runs each member's script or inferred Node, Jest, Vitest or Mocha suite.

  • An explicit root test script owns one aggregate report pair and runs once.
  • A publishable root without a script also gets its own implicit suite, where the manager allows that layout. Its implicit Node suite is omitted if it has no owned tests. Yarn Classic needs a private workspace root.
  • Package scripts keep their manager's argument and lifecycle behavior. Arguments reach each selected test command, and a root script receives them once.
  • Inferred suites skip nested members. Explicit scripts keep their own selection.
  • Dependency preparation may observe an empty test-file list for a root or member; it does not require every package to contain Node tests. An explicit test script keeps native zero-test behavior and must still produce any required reports. An implicit Node test suite for a root or member without owned files is omitted, with an informational “no tests” note in human output and JSON diagnostic events (not a warning) and no test action for that package. Explicitly selecting with.test-framework: node-test still fails if the suite has no owned files. Neither path falls back to recursive discovery of another member's tests.
  • Test frameworks and reporters must already be installed (see native reporting prerequisites).

Each package's current JUnit and LCOV files go into the bundle with the plan, logs and manifest summaries. Package names give stable report identities.

  • A failing assertion fails the command but lets later suites run, and available reports are kept.
  • A missing tool, malformed metadata or unresolved framework can stop the run before any suite starts.
  • Missing or invalid required reports are errors, including under task overrides. Oyzu never invents a pass for a command that writes no reports.

Hooks:

  • Oyzu pre and post hooks use the common task engine. A failed test blocks its success-only post hook.
  • Exact implicit commands get report instrumentation. Replacements in TOML keep their bodies and must write the required reports.
  • Member commands receive OYZU_TEST_REPORT and OYZU_COVERAGE_REPORT. Replacing a whole workspace task means providing each package's reports or explicit report collection paths.

What it does not do​

  • It doesn't rewrite package versions or locks, build archives, or run unrelated quality gates.
  • Test scripts can write host files and use the host environment and network. Offline manager flags only restrict the manager's own downloads.
  • Installed dependencies are used as they are. Nothing records where they came from.
  • pnpm and Yarn direct host member builds and quality defaults are incomplete. Modern Yarn releases are not supported.
  • A pnpm pnpm-workspace.yaml with a packages list selects workspace planning. Patch-only settings keep the single-project path.

See direct tests for how existing output is preserved and how to inspect a failed bundle.
