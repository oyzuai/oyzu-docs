Private Python indexes

CLI reference

Published from the canonical docs/reference/python-sessions.md file. Features marked experimental remain experimental; check support limitations before relying on them.

Use this when pip or uv should install from a private package index without a password in pip.conf, uv.toml, .netrc or environment variables. Each time you run pip or uv through oyzu, oyzu asks a local credential agent which index to use and gives the tool the password through its keyring support. You don't need the Python keyring package or any per-project authentication file.

Note: Experimental. You need a credential agent running on the same machine; oyzu doesn't include one. Supported on Linux with Python 3.12, pip 25.0 and uv 0.12, using Bash. Isolated oyzu build runs don't use this yet.

Configure​

Add the agent's address to your user or administrator configuration (not the project's oyzu.toml):

[python]
sessionEndpoint = "http://127.0.0.1:43199/session"
SettingValuesDefaultMeaning
python.sessionEndpointhttp://127.0.0.1:<port>/<path>, no user name, password, query or fragmentNot setThe local agent to ask for sessions. Remove it to go back to plain pip and uv

Project, local and command-line configuration and profiles can't set this value. User configuration isn't read in CI, so this doesn't work there.

Run pip or uv​

With Python and pip, or uv, on PATH:

oyzu exec -- python3 -m pip install --require-hashes -r requirements.txt
oyzu exec -- uv lock
oyzu exec -- uv sync --locked
eval "$(oyzu activate bash)"
pip install --require-hashes -r requirements.txt

An activated Bash shell routes python, python3, pip, pip3 and uv through oyzu when they're installed. oyzu exec also recognizes versioned names such as python3.12 and pip3.12. Running Python itself is unchanged; only python -m pip goes through the agent.

ToolSupported commands
pipinstall, download, wheel
uvlock, sync, pip install, pip sync

--help and --version run without asking the agent. Other commands, including uv run and uv publish, fail with PYTHON_OPERATION_UNSUPPORTED. Publish with oyzu publish.

What oyzu does for you​

  1. Sends the agent a POST with {"directory": "<working dir>", "tool": "pip" or "uv", "arguments": [...]}. This happens on every run, including warm or offline installs.

  2. Reads the agent's answer:

    {
      "index": "https://packages.example.com/simple/",
      "username": "reader",
      "credentialEndpoint": "http://127.0.0.1:43199/credential/session"
    }

    index is HTTP(S) with no credentials, query or fragment. username can't be empty. credentialEndpoint must be on 127.0.0.1.

  3. Adds the user name to the index URL and puts oyzu itself on PATH as keyring.

  4. Replaces the tool's index configuration for that run:

    • pip gets PIP_CONFIG_FILE set to the null device, PIP_INDEX_URL, PIP_KEYRING_PROVIDER=subprocess and no interactive prompts;
    • uv gets UV_NO_CONFIG=1, UV_DEFAULT_INDEX and UV_KEYRING_PROVIDER=subprocess;
    • extra-index and find-links variables and UV_CONFIG_FILE are removed.

  5. When the tool runs keyring get <service> <username>, oyzu POSTs {"ecosystem": "python", "service": "...", "username": "..."} to credentialEndpoint, which must answer {"password": "..."}. The agent should check the request against the index it approved.

Because pip and uv configuration files are switched off for the run, other options in them are ignored too. Requirements files, pyproject.toml, uv.toml and lock files aren't changed. Package caches and installed packages work as usual.

Credentials and security​

  • The password never goes into generated configuration, command arguments or environment variables. It passes through the keyring helper into the tool's memory, so the process can read it.
  • Read-only access has to be enforced by the index account the agent uses.
  • Helper failures show a generic message.
  • Denial or an unreachable agent stops the command before pip or uv starts, with no fallback to cached or direct access.

Output​

The tool's output and exit code pass through unchanged. With --json, they're captured in the usual oyzu exec result.

Errors​

CodeCauseFix
NATIVE_SESSION_CONFIGThe endpoint is set in project or local configurationMove it to user or administrator configuration
NATIVE_SESSION_UNAVAILABLEThe agent can't be reachedStart the agent and retry
NATIVE_SESSION_DENIEDThe agent refused the requestGet access granted; don't work around the agent
NATIVE_SESSION_INVALIDThe endpoint or credential endpoint isn't 127.0.0.1 HTTP, or the response is too largeFix the endpoint or the agent
PYTHON_SESSION_INVALIDThe response couldn't be read, or the index or user name isn't validFix the agent's response
PYTHON_ROUTING_CONFLICTYou passed an index, extra-index, find-links, keyring-provider, config-file, --isolated, --project or --directory optionRemove the option
PYTHON_OPERATION_UNSUPPORTEDThe command isn't in the supported listUse a supported command

Limits​

  • One index per run, for ordinary named packages (including hash-pinned requirements and uv locks).
  • Direct URL, VCS and path dependencies, source directives in requirements files, uv source and workspace overrides, and credentials in .netrc or other auth stores aren't covered.
  • Poetry and scripts that run pip or uv internally aren't covered.
  • Turning off pip and uv configuration isn't a network sandbox.
  • Temporary files may be left behind if oyzu is killed.
  • Linux and Bash only. Windows and macOS aren't supported yet.
