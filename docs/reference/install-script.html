Install script

CLI reference

Published from the canonical docs/reference/install-script.md file. Features marked experimental remain experimental; check support limitations before relying on them.

install.sh and install.ps1 install the oyzu executable from a GitHub release with one command. They pick the release asset for your platform, check its SHA-256 digest and put oyzu in a folder of your own. They need no administrator rights. They then run oyzu shell install, so your shells activate oyzu and both oyzu and its tool shims are on your PATH.

Note: Every release is a preview. Releases are binaries and notices published on the public oyzuai/oyzu-releases repository, and both scripts default to it, so you need no account or token. No release has been published there yet. Until one is, a run stops with no published release. The scripts don't check release provenance (the *.sigstore.json files) yet.

Install​

On Linux or macOS:

curl -fsSL https://docs.oyzu.ai/install.sh | sh

On Windows, in PowerShell:

irm https://docs.oyzu.ai/install.ps1 | iex

A GitHub token is optional. It lifts the anonymous API limit, or lets you install from a private repository named in OYZU_RELEASE_REPO. With the GitHub CLI signed in:

curl -fsSL https://docs.oyzu.ai/install.sh | GH_TOKEN=$(gh auth token) sh
$env:GH_TOKEN = (gh auth token); irm https://docs.oyzu.ai/install.ps1 | iex

A successful run names the release, prints one summary line (tag, asset, SHA-256 digest, location), the installed oyzu --version and the result of oyzu shell install. Release values are placeholders here:

Installing oyzu <tag> for linux/x86_64 from oyzuai/oyzu-releases
Installed oyzu <tag> (oyzu-linux-x86_64, sha256:<digest>) to /home/you/.oyzu/bin/oyzu
oyzu <version> (<build>; x86_64-unknown-linux-gnu; build <id>)

Shells and PATH set up
  activation  bash  /home/you/.bashrc
  login-path  bash  /home/you/.profile
Next Step: Open a new terminal (and restart IDEs) so they pick up the new PATH.

To use Preview plugins, run oyzu config set --global plugins.preview true once. It is a user-level setting that applies to all your projects, and Stable defaults stay unchanged.

Read it before you run it​

Piping a download into a shell runs whatever the server sent. Each script is under 250 lines, so you can read it first:

curl -fsSL https://docs.oyzu.ai/install.sh -o install.sh
less install.sh
sh install.sh
irm https://docs.oyzu.ai/install.ps1 -OutFile install.ps1
Get-Content install.ps1
powershell -ExecutionPolicy Bypass -File .\install.ps1

Both are served from the documentation site over HTTPS.

Which release and asset​

Without a version, the script reads the newest 30 releases and takes the newest one that is not a draft and has an executable for your platform. Previews count, and every release is one.

HostAsset
Linux x86_64 / aarch64 (glibc)oyzu-linux-x86_64 / oyzu-linux-arm64
Linux with musl (Alpine)oyzu-linux-x86_64-musl / oyzu-linux-arm64-musl
macOS Intel / Apple siliconoyzu-darwin-x86_64 / oyzu-darwin-arm64; a shell under Rosetta still gets arm64
Windows x86_64 / ARM64oyzu-windows-x86_64.exe / oyzu-windows-arm64.exe, by the native architecture even in an emulated shell

If the release also has oyzu-shim-<platform>, it is installed beside oyzu as oyzu-shim. Releases so far publish no musl assets, so a musl host gets the no asset error.

On macOS and Windows the script also downloads the same release's Linux oyzu for your architecture (oyzu-linux-x86_64 or oyzu-linux-arm64), checked the same way. Isolated builds (oyzu build --isolated) run that Linux oyzu inside the container. A Linux host doesn't need it: its own oyzu runs there.

What it changes​

  1. Downloads the asset into a temporary folder and compares its SHA-256 with the digest GitHub reports for that asset. A mismatch or a missing digest stops the install.
  2. Runs the new oyzu --version from the temporary folder. An executable that can't run on this host leaves an existing install alone.
  3. Creates the install folder and replaces oyzu (and oyzu-shim) there, with the executable bit set. Running it again upgrades or reinstalls.
  4. On macOS and Windows, runs oyzu engine install --linux with the downloaded Linux oyzu. This installs the pair as the engine package of the new oyzu, so --isolated works. It prints Installed the Linux engine for isolated builds. If the release has no Linux oyzu for your architecture, or the step fails, oyzu stays installed and the script says so; only isolated builds are affected.
  5. Prints one line with the tag, asset, digest and location, then the version.
  6. Runs the installed oyzu shell install, unless you skipped it.

The scripts never use sudo and never install toolchains.

Shell and PATH setup​

The last step runs oyzu shell install with the new executable. It needs no network and edits only the files below. Running it again changes nothing.

WhatWhere
Shell activation: bash, zsh, PowerShell 7 (each one found)~/.bashrc, $ZDOTDIR/.zshrc or ~/.zshrc, and the PowerShell 7 current-user profile
oyzu and the tool shims on the persistent PATH, Windowsyour user Path in the registry (HKCU\Environment), with %VARIABLE% entries unexpanded, announced to running programs
oyzu and the tool shims on the persistent PATH, Linux and macOSa marked block in your login profile (~/.bash_profile, ~/.bash_login or ~/.profile, whichever exists first; ~/.zprofile for zsh)

The shims let IDEs, GUI programs, services and scripts that never start a shell run node, go or cargo at the version the project locks, without oyzu exec --. Programs that are already open keep the PATH they started with, so restart them or open a new terminal.

If setup fails, the install still stands. The script says so on standard error and prints the command to run again. fish and Windows PowerShell 5.1 are not configured, so add the folders yourself.

With --no-modify-path (-NoModifyPath, OYZU_NO_MODIFY_PATH=1) the script changes no profile or PATH. If the folder isn't on PATH, it prints how to set things up later:

ShellLine
any~/.oyzu/bin/oyzu shell install (Windows: & "$env:LOCALAPPDATA\Oyzu\bin\oyzu.exe" shell install)
PowerShell, this session$env:Path = "$env:LOCALAPPDATA\Oyzu\bin;$env:Path"

See oyzu shell for what each file receives and how to undo it.

Upgrade and uninstall​

Run the same command again to move to the newest release, or pass a version to switch to that one.

To uninstall, run oyzu shell remove to undo the shell and PATH setup, then delete the two files (and the folder if it is empty):

rm -f ~/.oyzu/bin/oyzu ~/.oyzu/bin/oyzu-shim
Remove-Item "$env:LOCALAPPDATA\Oyzu\bin\oyzu.exe", "$env:LOCALAPPDATA\Oyzu\bin\oyzu-shim.exe"

Tools that oyzu installed for projects live in its own store, not in this folder, so deleting these files doesn't remove them.

Security​

  • Integrity: the digest comes from the GitHub releases API over HTTPS, and the download must match it. This shows the bytes are the ones GitHub holds for that release asset. It doesn't show who built them, because the scripts don't check release provenance yet.
  • Transport: install.sh restricts curl to HTTPS, including redirects, unless OYZU_API_BASE or OYZU_DOWNLOAD_BASE names a plain http: test server.
  • Tokens: a token is sent only in a request header to the GitHub API. install.sh gives it to curl on standard input, never on the command line, so it needs curl when you use a token (wget is used only without one). curl and PowerShell drop the header when GitHub redirects a download to its storage host. The scripts never print a token.
  • Scope: files go to the install folder and a temporary folder that is removed afterwards. oyzu shell install then edits the profiles listed under Shell and PATH setup. --no-modify-path skips it.

Platforms and requirements​

ScriptRuns onNeeds
install.shLinux, macOS; also Git Bash on WindowsPOSIX sh, awk, curl or wget, and sha256sum, shasum or openssl
install.ps1Windows x86_64 and ARM64Windows PowerShell 5.1 or PowerShell 7

install.sh uses no bash features, jq or Python. Running install.ps1 under PowerShell on macOS or Linux stops and points you to install.sh.

The scripts are tested on Linux and Windows (x86-64). macOS, musl and ARM64 aren't tested yet.

Exit status​

StatusMeaning
0Installed
1Failed: network, HTTP error, no release or asset for this platform, the executable doesn't run, or the folder can't be written
2Usage error (unknown option or missing value)
3Integrity refusal: the digest differs, the release reports none, or no SHA-256 tool is available

install.ps1 sets the process exit status when run with powershell -File install.ps1. Under irm ... | iex it doesn't exit, because that would close your window. It prints the error and sets $LASTEXITCODE.

Failures and recovery​

Errors start with oyzu install: and leave an existing install unchanged.

MessageCauseRecovery
GitHub answered 404 Not Found for the release list of <repo> ... privateOYZU_RELEASE_REPO names a private repository and no token was given, or it doesn't existPass GH_TOKEN with access, for example GH_TOKEN=$(gh auth token)
GitHub answered 404 Not Found ... with your tokenThe token can't read the repository, or the tag or asset doesn't existCheck the tag and the token's repository access
GitHub rejected the token ... (HTTP 401)Invalid or expired tokenCreate a new token or run gh auth login
GitHub refused ... (HTTP 403)Anonymous API rate limit (60 requests an hour) or missing permissionWait, or pass GH_TOKEN
no published release of oyzuai/oyzu-releases has <asset>No release has an executable for this platform (musl, other CPUs), or no release is published yetBuild from source
release <tag> ... has no <asset>That release lacks this platformChoose another --version
<asset> ... has digest ..., but the release reports ...The download doesn't match the published digestRetry. If it repeats, don't use the file, and report it
release <tag> reports no SHA-256 digestThe release API returned no digest for the assetChoose another release
could not connect to download ...Offline, DNS or proxy failureCheck the network. curl, wget and PowerShell honor the usual proxy settings
the downloaded <asset> does not run on this hostWrong ABI or a damaged downloadBuild from source, or report the platform
cannot write <path>No permission, or oyzu.exe is running on WindowsChoose --dir, or close oyzu and retry
