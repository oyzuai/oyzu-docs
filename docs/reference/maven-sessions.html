Private Maven repositories

CLI reference

Published from the canonical docs/reference/maven-sessions.md file. Features marked experimental remain experimental; check support limitations before relying on them.

Use this when Maven should download from private repositories without passwords in settings.xml. A local credential agent tells oyzu which repositories are allowed and supplies the credentials. oyzu uses the same agent for two things:

  • running mvn yourself through oyzu exec or an activated shell, where Maven gets the password in memory;
  • oyzu build for Maven projects, where oyzu downloads the dependencies itself and Maven never sees the password (see Captured build acquisition).

Note: Experimental. You need a credential agent running on the same machine; oyzu doesn't include one. Supported on Linux with Maven 3.9.11, JDK 17 and Bash.

Configure​

Add the agent's address to your user or administrator configuration (not the project's oyzu.toml):

[maven]
sessionEndpoint = "http://127.0.0.1:43199/session"
SettingValuesDefaultMeaning
maven.sessionEndpointhttp://127.0.0.1:<port>/<path>, no user name, password, query or fragmentNot setThe local agent to ask for sessions. Remove it to go back to plain Maven and Maven Central

Project, local and command-line configuration and profiles can't set this value. User configuration isn't read in CI, so this doesn't work there.

Run Maven​

You need Maven 3.9.11 and a JDK with java, javac and jar on PATH:

oyzu exec -- /opt/maven/bin/mvn verify
# or, with Maven on PATH:
eval "$(oyzu activate bash)"
mvn verify

Use the mvn from a Maven installation; mvnw and other wrappers aren't supported. --help and --version run without asking the agent. You don't need any authentication files or extensions in the project.

What the agent returns​

oyzu sends the agent a POST with {"directory": "<working dir>", "tool": "mvn", "arguments": [...]}. The agent answers with one or more mirror mappings:

{
  "sources": [
    {
      "id": "approved-libraries",
      "mirrorOf": "company-libraries",
      "access": {
        "repository": "https://packages.example.com/maven/",
        "username": "reader",
        "credentialEndpoint": "http://127.0.0.1:43199/credential/session"
      }
    }
  ]
}
FieldRules
sources1 to 64 entries, in Maven mirror order (exact matches before wildcards)
idUnique. Letters, digits, -, _ or .. Can't be oyzu-source-denied
mirrorOfA Maven mirror selector. Unique across entries
access.repositoryHTTP(S) URL with no credentials, query or fragment
access.usernameNot empty
access.credentialEndpointOn 127.0.0.1. A GET returns the password as UTF-8 text

Use "mirrorOf": "*" for one repository that serves everything, or separate entries for central, company-libraries, company-plugins and so on. Maven matches repository IDs, not group names.

What oyzu does for you​

  1. Asks the agent before doing anything, even when Maven's cache is warm.
  2. Compiles a small bundled Maven extension against your Maven's libraries.
  3. Lets Maven read your normal settings.xml files (including -s and -gs). The extension then:
    • keeps your blocking mirrors;
    • adds the agent's mirrors, plus a catch-all that blocks every other repository, including ones declared in POMs;
    • fetches each password into memory and authenticates only to that mirror's exact URL.
  4. Removes the temporary extension and files when Maven finishes or fails.

An existing non-blocking mirror in your settings must match an agent mapping's URL, selector and layout (its ID may differ), or the run fails and names the settings file. <server> credentials in your settings are never used as a fallback. Profiles, properties, proxies and JVM settings work as usual.

Maven downloads directly from the repositories; oyzu doesn't proxy the traffic.

Isolated build acquisition​

With maven.sessionEndpoint set, oyzu build asks the agent for a session before it prepares a Maven project. The request has "tool": "mvn" and "arguments": ["oyzu-build-acquire"], a marker for the agent rather than a real Maven command. The agent answers with a single repository:

{
  "repository": "https://packages.example.com/maven/",
  "username": "reader",
  "credentialEndpoint": "http://127.0.0.1:43199/credential/session"
}

The repository URL must end in /. oyzu fetches the password into memory and downloads the dependencies itself with Basic authentication. The build containers have no network access and never see the password; the build then runs offline from what was downloaded.

  • Without the setting, dependencies come from Maven Central.
  • If the agent denies or fails, the build stops. It never falls back to Maven Central.
  • Snapshot versions are allowed only from administrator-listed snapshot repositories.
  • If a plugin needs a dependency at build time that wasn't declared, the offline build fails. Declare it through the plugin's Maven configuration and build again. oyzu doesn't rerun the build online.

Credentials and security​

  • Passwords never go into settings files, command arguments or environment variables. When you run mvn yourself, the password is in Maven's memory, so plugins can read it. With oyzu build, Maven never receives it.
  • The temporary files contain the credential endpoint, not the password, but treat them as sensitive.
  • Read-only access has to be enforced by the repository account the agent uses.
  • Denial or an unreachable agent stops the command before Maven starts, with no fallback.

Output​

Maven's output and exit code pass through unchanged. With --json, they're captured in the usual oyzu exec result.

Errors​

CodeCauseFix
NATIVE_SESSION_CONFIGThe endpoint is set in project or local configurationMove it to user or administrator configuration
NATIVE_SESSION_UNAVAILABLEThe agent can't be reachedStart the agent and retry
NATIVE_SESSION_DENIEDThe agent refused the requestGet access granted; don't work around the agent
NATIVE_SESSION_INVALIDBad endpoint, or a mapping has a bad repository or no user nameFix the endpoint or the agent
MAVEN_SESSION_INVALIDThe agent's response couldn't be read, or has no mappings or more than 64Fix the agent's response
MAVEN_SESSION_PREPAREThe JDK tools couldn't compile the extensionInstall a working JDK and Maven

Publish with oyzu publish

Limits​

  • Plugins that make their own network calls aren't covered.
  • Proxy authentication and custom TLS settings aren't supported yet.
  • Credential rotation during a run, and cleanup after oyzu is killed, aren't handled.
  • Linux and Bash only, with Maven 3.9.11. Windows, macOS and other Maven versions aren't supported yet.
