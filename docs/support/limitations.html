Known limitations

This page describes the most important constraints a developer should know before choosing Oyzu.

Early-stage distribution​

The supported documentation path builds Oyzu from an authorized source checkout. A public one-line installer or public package-manager distribution has not yet been verified or documented.

Native ecosystems​

Tool versions, operating systems, builder families, dependency acquisition and caching vary in support. The local-build reference and tool-management reference contain the specific qualified cases.

Local cache​

The local action cache is on by default and experimental. The remote OCI cache is experimental, unsigned and verified on Linux only, against a small set of registries. Reuse keys cover what Oyzu can see; they are not a claim of fully hermetic hashing. See Cache build results.

Remote service​

The remote client includes an experimental command surface but has not been qualified against a deployed production worker service. See remote runs.

Documentation accuracy​

  • Public pages reflect a curated allowlist, not the entire internal docs source tree.
  • Real terminal captures need source revision, platform and process evidence.
  • Illustrative diagrams and command snippets are explicitly distinguished from executed qualification runs.
  • The site uses Segoe UI when installed; systems without the licensed font use a fallback. Typography on another host is not verified as exact.

Reporting a problem​

If an example conflicts with your installed CLI version, capture oyzu --version, the relevant help output, the platform and the command's actual error. A change to the canonical CLI reference should accompany the implementation fix.
