oyzu cache

Inspect or clear the local action cache. When nothing that affects a build stage has changed (toolchain, dependencies, stage definition, the source files in its scope, the outputs it consumes), oyzu build reuses the stored result instead of running the stage again. The cache is per user and shared by all your projects.

oyzu cache [OPTIONS] <COMMAND>
SubcommandWhat it does
statusShow where the local action cache lives, how large it is and how many entries it holds
clearRemove every cached action result. Build bundles are never touched
explain <TARGET>Show why a target's or stage's cache key last changed: the first key component that differs from the build before

None of the subcommands has options of its own; the global options apply.

Status

The local action cache is experimental. Reuse is local to one user and machine; a shared remote OCI cache is configured separately (action cache).

cache status​

$ oyzu cache status
Action cache
​
  Location   C:\Users\you\AppData\Local\Oyzu\cache\actions (default per-user location)
  Entries    552 results · 2841 blobs
  Size       9.9 GiB of 10.0 GiB retention budget
  Docker     5 images · 2.6 GiB of 20.0 GiB image budget (cache.dockerMaxMiB)
  Local use  enabled
​
Reuse is local to this user and machine. Ephemeral CI runners start empty; shared caching is a later milestone.
Use `oyzu cache clear` to empty it, or `oyzu build --no-cache` to bypass it once.

The default location is $XDG_CACHE_HOME/oyzu/actions (or ~/.cache/oyzu/actions) on Linux, ~/Library/Caches/Oyzu/actions on macOS and %LocalAppData%\Oyzu\cache\actions on Windows. cache.dir in user or machine configuration moves it. At the end of a build, least-recently-used results are evicted when the store exceeds its 10 GiB budget.

cache explain​

oyzu cache explain [OPTIONS] <TARGET>
ArgumentMeaning
<TARGET>A target id, or one stage's action id such as api:build
$ oyzu cache explain project:build
Cache key explanation  project:build
​
  project:build (stage)
    Key        d7dbf45c44f6 · since run 7340-1792534273646063700 · last seen run 7340-1792534273646063700 (2026-10-20T22:11:22Z)
    Result     stored · the next build with these inputs reuses it
    Changed    since run 13316-1792534220089452300: prepared dependencies changed (also: source files in scope; action definition: argv, env.OYZU_VERSION and 2 more; output of an earlier action: project:prepare)
​
Keys come from the toolchain, dependencies, stage definition, source in scope and consumed outputs.
Use `oyzu build --explain` to see this for every stage of a build.

It reads recorded keys only; it runs nothing. Changed names the first key component that differs from the previous build of that stage, then the others. oyzu build --explain prints the same reasoning for every stage right after a build.

cache clear​

oyzu cache clear

Removes every cached action result. Build bundles in dist/ hold their own copies and are never touched. clear needs exclusive access: while a build is using the cache it fails with a retry diagnostic, so retry after the build finishes. Do not delete store.lock by hand to get around this.

To skip the cache for a single build instead, use oyzu build --no-cache; to turn it off, set cache.local = false.

StatusWhen
0Success
1An operation error, such as a store that a running build holds
3cache.dir set in a project file (CONFIG_SCOPE); it is allowed only in user or machine configuration
