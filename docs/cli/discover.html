oyzu discover

Show what Oyzu sees in this folder: each target (one buildable unit, such as a Go module, an npm package or a Cargo package), the builder that handles it, whether build.yaml or detection chose it, and where it lives. Discovery reads build.yaml and your native files. It never runs project code.

oyzu discover [OPTIONS]

Options​

OptionDescription
--writeDeclare every folder build.yaml leaves out, creating build.yaml if needed
--checkWrite nothing; exit non-zero if a tracked folder holds a build that build.yaml neither declares nor lists under exclude:

Plus the global options.

With a build.yaml, only its builds are built. A build may leave out uses when exactly one builder recognizes its folder. Folders where discovery recognizes a build that build.yaml leaves out are listed, never built. Inside Git, only tracked files count.

Examples​

See what Oyzu found​

$ oyzu discover
1 target · 6 tasks discovered without running project code
Project root: …\hello
​
project · go/app
  Chosen by          detected from project files
  Location           .
  Manager            go
  Version            0.0.0
  Part of builds     build, format-check, lint, test
  Development tasks  format, install
​
Target names are what `oyzu build <target>` accepts.
Next steps:
  oyzu run list      every task and the command it runs
  oyzu build --plan  preview the build stages without running them
Use --json for the complete discovery record, including each task's environment and dependencies.

Part of builds are the stages oyzu build runs for this target; Development tasks are available through oyzu run only.

Declare the builds in build.yaml​

Zero configuration is fine for a single project. In a repository with several projects, declare them so a new folder never silently becomes a build:

$ oyzu discover --write
Created build.yaml with 1 build
Build    Uses      Folder
project  node/app  .
Only folders with Git-tracked files were considered.
Review the change, then add `oyzu discover --check` to CI to catch new folders.

The file it wrote:

# yaml-language-server: $schema=https://github.com/oyzuai/oyzu/releases/latest/download/build.yaml.schema.json
builds:
  project: {uses: node/app, path: .}

After that, oyzu discover reports Chosen by build.yaml and confirms that build.yaml declares every folder where a build was discovered.

Keep build.yaml complete in CI​

$ oyzu discover --check
Build inventory is current · 1 build declared
Only folders with Git-tracked files were considered.

When a folder is not declared (here, a project with no build.yaml yet), it exits 1 and prints the line to add:

$ oyzu discover --check
error[INVENTORY_UNDECLARED]: there is no build.yaml; discovery finds 1 build here
Folder  Recognized by  Line to add under builds:
.       go/app         project: {path: .}
Only folders with Git-tracked files were considered.
fix: run `oyzu discover --write` to declare them, or list the folders that are deliberately not builds under exclude: in build.yaml

JSON output​

oyzu --json discover returns the full discovery record. It is trimmed here to one target and one task; a project with a build.yaml also has an inventory object (undeclared, excluded, tracked, workspaceMembers), and plugin_selection is null in this project:

$ oyzu --json discover
{
  "root": "…\\hello",
  "targets": {
    "project": {
      "builder": "go/app",
      "builder_selection": "inferred",
      "manager": "go",
      "name": "project",
      "path": "…\\hello",
      "version": "0.0.0"
    }
  },
  "tasks": {
    "project:build": {
      "argv": [
        "go",
        "build",
        "./..."
      ],
      "availability": null,
      "build_stage": true,
      "cwd": "…\\hello",
      "depends_on": [],
      "env": {},
      "mutates_source": false,
      "name": "build",
      "provider": "go",
      "reports": [],
      "shell": false,
      "stdout_must_be_empty": false,
      "target": "project"
    }
  }
}

builder_selection is explicit when build.yaml chose the builder and inferred when detection did; discovery holds every detector's observations and the evidence behind each selection (formatter, linter, package manager and so on).

--check and --write return a build-inventory record (here for a project with no build.yaml, so --check exits 1):

$ oyzu --json discover --check
{
  "declared": 0,
  "excluded": [],
  "inventory": false,
  "kind": "build-inventory",
  "mode": "check",
  "outcome": "undeclared",
  "path": "…\\hello\\build.yaml",
  "skippedBuildFiles": [],
  "tracked": "git",
  "undeclared": [
    {
      "builders": [
        "go/app"
      ],
      "entry": "project: {path: .}",
      "name": "project",
      "path": "."
    }
  ],
  "warnings": [],
  "workspaceMembers": []
}

Exit status​

StatusWhen
0Discovery succeeded; with --check, every folder is declared or excluded; with --write, the file was written or nothing was needed
1--check found an undeclared folder (INVENTORY_UNDECLARED), or --write needs a choice because several builders recognize one folder
3build.yaml or oyzu.toml is invalid

Common problems​

SymptomFix
A project you expected is missingMake sure its files are tracked by Git (git add); untracked folders are ignored. Check that its native manifest is at the folder root.
A folder is a build by accident (fixtures, examples)List it under exclude: in build.yaml.
Needs a choice: several builders recognize one folderAdd the build to build.yaml with an explicit uses: (the row shows an example line with a placeholder).
No targets foundRun from the project root, or pass -C <folder>.
