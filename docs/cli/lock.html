oyzu lock

Write or check OS package locks for Docker targets. For each Docker target, oyzu lock builds every stage that contributes to the image once, compares the stage's package database with its base image's, and records each newly installed Debian or Alpine package (URL, version, checksum and Package URL) in debs.lock.yaml or apks.lock.yaml next to the Dockerfile. It never parses the RUN shell. Commit the lock with your change, and don't edit it by hand.

Once a lock exists, oyzu build installs from it: RUN steps see only a local repository that serves the locked files.

Tool versions are locked by oyzu pin, not by this command.

oyzu lock [OPTIONS]

Note: OS package locks are experimental and need a Docker engine with BuildKit (docker buildx). See OS package locks for limits.

Options​

OptionDescription
--checkWrite nothing; exit non-zero if a lock is missing or stale
--update [<SELECTOR>...]Re-observe with fresh base image digests and no build cache. Optional selectors name a target or a lock path; none means every lock
--inputsList every locked package and base image for Renovate; resolves nothing
--store <DIR>Use this tool store (which also holds installed plugins) instead of the shared user store

The global options also apply.

Examples​

oyzu lock                   # write missing locks and regenerate stale ones
oyzu lock --check           # fail if any lock is missing or stale; writes nothing
oyzu lock --update          # re-observe every lock with fresh bases and no build cache
oyzu lock --update api      # re-observe only the api target's locks
oyzu lock --inputs --json   # list locked packages for Renovate; resolves nothing

A lock that is already current is left alone. In a project with no Docker target that installs OS packages, it prints No Docker target installs OS packages; there is nothing to lock.

--check works offline and fits a CI step: it fails when a Dockerfile change installs a package the lock doesn't cover. A tag in FROM keeps the digest already in the lock until you run --update.

JSON output​

--json returns one record with mode (write, update, check or inputs) and outcome (written or current for writes, current or stale for --check, listed for --inputs). Each --check entry has a status (current, stale or missing) and, when not current, code: OS_PACKAGE_LOCK_STALE and fix: oyzu lock. --inputs entries list each base image and package in the form Renovate reads.

Exit status​

StatusWhen
0Locks written or already current; --check found every lock current
1An operational error, such as a failed observation build
2Invalid arguments
3Configuration or policy validation failed
4--check found a missing or stale lock

Common errors​

CodeFix
OS_PACKAGE_LOCK_STALERun oyzu lock and commit the result.
OS_PACKAGE_UNRESOLVABLEA package was installed from a file, or its version disappeared upstream. Install from a configured repository, or run oyzu lock again.
OS_PACKAGE_UNVERIFIEDapt reported a signature problem. Fix the repository's signing key in the image.
OS_PACKAGE_NOT_LOCKEDA RUN step asked for a package the lock doesn't contain. Run oyzu lock --update, or remove the install.
OS_PACKAGE_UPDATE_SELECTOR--update can't select a single package. Update the whole lock or its target.
