oyzu run

List the development tasks Oyzu found in your project, or run one. Tasks come from your native files (such as Cargo.toml, go.mod or the scripts in package.json) and from oyzu.toml. Running a task uses the project's locked tools, so oyzu run test behaves the same on every machine.

oyzu run [OPTIONS] [TASK] [-- <ARGS>...]
ArgumentMeaning
[TASK]Task to run, such as test or cli:build. Omit it, or use list, to list tasks
[ARGS]...Arguments passed to the task's own command, written after --

Options​

OptionDescription
--store <DIR>Use this verified tool store instead of the shared user store
--remoteRun the task on a platform pool against the pushed HEAD and follow it here
--download <DIR>With --remote: download the run's outputs into this directory

Plus the global options. --toolset NAME runs the task with a toolset's tools instead of [tools].

--remote is an experimental client of the platform's remote-run API and needs a platform account (remote runs). Everything else on this page works without one.

Examples​

List tasks​

$ oyzu run list
Available tasks · 6 across 1 target
​
Task                  Source         Command
project · go/app (6)
project:build         Inferred · go  go build ./...
project:format        Inferred · go  gofmt -w .
project:format-check  Inferred · go  gofmt -l .
project:install       Inferred · go  go mod download
project:lint          Inferred · go  go vet ./...
project:test          Inferred · go  go test ./...
​
Run one with: oyzu run <task>   (extra arguments go after --)
Commands show argv; task dependencies and hooks may also run. Use --json for full task records.

The same command in an npm package shows the scripts it found and the tools Oyzu infers for the remaining stages:

$ oyzu run list
Available tasks · 6 across 1 target
​
Task                  Source          Command
project · node/app (6)
project:build         Inferred · npm  npm run build
project:format        Inferred · npm  prettier --write .
project:format-check  Inferred · npm  prettier --check .
project:install       Inferred · npm  npm ci
project:lint          Inferred · npm  eslint .
project:test          Inferred · npm  npm run test
​
Run one with: oyzu run <task>   (extra arguments go after --)
Commands show argv; task dependencies and hooks may also run. Use --json for full task records.

Task IDs are target:task. When a project has only one target with that task, the short name (test) is enough; with several targets, use api:test.

Run a task​

  › project · Testing  Running

{"Time":"2026-10-20T23:04:08.6018143-04:00","Action":"pass","Package":"example.com/oyzu/hello","Elapsed":0.381}

The native tool's own output (here the Go test runner's event stream, trimmed with …) passes through unchanged between Oyzu's lifecycle rows. Standard input stays connected, so interactive tasks work. A task with a recorded bundle also writes its full output to dist/logs.

Pass arguments to the task​

Everything after -- goes to the task's command:

oyzu run test -- -run TestGreeting -v

Run on a platform pool​

oyzu run test --remote

This runs the task against the pushed HEAD on a pool and follows it in your terminal. Ctrl+C cancels the remote run.

Exit status​

oyzu run TASK exits with the task's own exit status, so oyzu run test && deploy works as you expect. Oyzu's own failures use the shared codes; the most common is 5 for a task that does not exist. With --remote, a non-zero exit on the pool is returned as is; a refused run exits 2 and an interrupt exits 130.

Common errors​

$ oyzu run nosuch
  · Setup  Loading configuration and discovering tasks
✗ TASK_NOT_FOUND: no task "nosuch" in …\hello. Available tasks: build, format, format-check, install, lint, test. Run oyzu run to list tasks, or oyzu -C <project> run nosuch
  Next: Check the selected directory and name; use oyzu -C <project> to select a project.
  Invocation: 55840-1792551849171752700-1
  oyzu 0.1.0-local.564f462704df (debug; x86_64-pc-windows-msvc; build 1792551563) · windows/x86_64
  Executable: …\oyzu.exe
  Directory: .
CodeFix
TASK_NOT_FOUND (exit 5)Check the name with oyzu run list, or select the right project with -C.
TASK_PROJECT_REQUIRED (exit 5)You are outside a project. Outside a project, oyzu run lists nearby projects by folder instead; cd into one or pass -C.
TOOL_LOCK_STALE (exit 4)The lock does not cover a requirement. Run oyzu pin, then retry.
