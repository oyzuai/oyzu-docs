oyzu plugins

Find builder plugins, see which one each target of this project uses and why, and update the selections locked in oyzu.lock. Plugins are builders that run as separate processes (the first is the Go builder, oyzu/go); most targets today use built-in builders.

oyzu plugins [OPTIONS] <COMMAND>
SubcommandWhat it does
search [QUERY]Browse or search the plugin references the catalogs offer
versions <REFERENCE>Show a reference's known releases and why each can or cannot be selected here
info <REFERENCE[@VERSION]>Show a release's package, contracts, platforms, routes and verification
listList the plugin releases installed in the plugin store
currentShow this project's locked plugin selections, their install state and eligibility
explain [TARGET]Explain which plugin a target uses and why, with the ways to change it
update [REFERENCE[@SELECTOR]]...Update locked plugin selections within their adopted major, showing before and after

The inspection commands read the verified cached catalog, the plugin store and oyzu.lock. They never download or launch a plugin, run a project tool or change a file. Only --refresh may update the verified catalog cache. update is the one command that changes anything.

Status

Experimental. The official catalog offers preview releases, which are selectable only after oyzu config set --global plugins.preview true. See plugin inspection and the Go builder preview.

Options​

All inspection subcommands (search, versions, info, list, current, explain) take:

OptionDescription
--store <DIR>Use this tool store instead of the shared user store
--refreshUpdate the verified catalog cache from permitted sources first; installs no plugin
--offlineNever use the network; read only the verified cached catalog

search also takes --type <TYPE>: show only plugins serving this core capability. Possible values: build (build plugins, the build capability). update takes --dry-run, --store and --offline (see below). The global options apply to all.

Lists the plugin store only. Other projects' selections are not known here: the store keeps no
inventory of the projects that use it.

plugins current and plugins explain​

oyzu plugins current [OPTIONS]
oyzu plugins explain [OPTIONS] [TARGET]
ArgumentMeaning
[TARGET]The target, by name or path (omit for every plugin-backed target)

In a project whose targets all use built-in builders:

$ oyzu plugins explain --offline
No target here uses a plugin

Every target uses a built-in builder. Declare uses: <reference> in build.yaml, or find plugins with oyzu plugins search.

Nothing was installed, launched or written.

For a plugin-backed target, explain prints the same Selection record oyzu build prints: which release, why it was chosen, and how to change it. current shows each locked selection with its install state and eligibility.

plugins update​

oyzu plugins update [OPTIONS] [REFERENCE[@SELECTOR]]...
Argument / optionDescription
[REFERENCE[@SELECTOR]]...References to update, each optionally with @v<major>, @<version> or @sha256:<digest> (omit for all)
--dry-runPreflight and show the lock change without writing oyzu.lock
--store <DIR>Use this tool store instead of the shared user store
--offlineNever use the network; update from the cached catalog only
oyzu plugins update                  # every locked selection, within its major
oyzu plugins update go/app@v2        # adopt major 2 explicitly
oyzu plugins update go/app@1.4.2     # select exactly 1.4.2
oyzu plugins update go/app@sha256:…  # restore one exact release (the printed undo)
oyzu plugins update --dry-run

A routine update moves to the newest eligible release inside the adopted major, never to an older one and never to a preview. Each new release is installed and verified first; oyzu.lock is rewritten only when every requested selection passes, in one transaction. A withdrawn, revoked or rebound release, or an unusable catalog, fails without changing the lock. Nothing is launched. With no plugin locked:

$ oyzu plugins update --dry-run --offline
oyzu.lock selects no plugin; nothing to update
…
Nothing was launched and no file changed.

Exit status​

StatusWhen
0Success, including "nothing to update"
1An unknown target for explain (PLUGIN_TARGET_UNKNOWN), a refused or unusable catalog, an update whose verification failed
2Invalid arguments

A related code comes from oyzu build --frozen: PLUGIN_LOCK_MISSING (exit 4) when oyzu.lock lacks the approved plugin selection. Restore the complete lock rather than resolving a new one.
