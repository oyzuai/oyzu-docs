oyzu exec, oyzu which and oyzu env

Three commands for using a project's pinned tools without activating your shell:

  • oyzu exec -- COMMAND runs a command with this project's locked tools first on PATH.
  • oyzu which COMMAND prints the path of the executable the project would use.
  • oyzu env shows the environment Oyzu composes for the project, or prints it as shell assignments.

All three use the frozen selection in oyzu.lock: they use what is locked and installed. A command that is not part of the selection is not found.

oyzu exec​

oyzu exec [OPTIONS] -- <COMMAND>...
ArgumentMeaning
<COMMAND>...Command and arguments to run, written after --
OptionDescription
--store <DIR>Use this tool store instead of the shared user store
--offlineUse installed tools and admitted cached archives without networking

Plus the global options; --toolset NAME runs with that toolset's tools.

$ oyzu exec -- go version
go version go1.22.12 windows/amd64

The project pins Go 1.22 in oyzu.toml, so go resolves to the locked 1.22.12 whatever else is on your PATH. This is how this repository runs Cargo: oyzu exec -- cargo test --locked.

Everything after -- is passed to the child unchanged, and the child inherits standard input, output and error. oyzu exec exits with the child's exit status.

With --json, the child's output is captured and returned in one record, with its exit status preserved:

$ oyzu --json exec -- go version
{
  "capture": {
    "encoding": "utf-8-lossy",
    "stderr": "pipe",
    "stdin": "inherited",
    "stdout": "pipe",
    "streaming": false,
    "tty": false
  },
  "exitCode": 0,
  "invocationId": "58216-1792552148201584600-1",
  "stderr": "",
  "stdout": "go version go1.22.12 windows/amd64\n"
}

The capture object says what that means for the child: piped (not a terminal), not streamed live, and decoded as UTF-8 with replacement characters for invalid bytes.

Project [env] values and env._.path entries apply to exec only in a trusted folder.

oyzu which​

oyzu which [OPTIONS] <COMMAND>
ArgumentMeaning
<COMMAND>Command name to look up, such as cargo or node
OptionDescription
--store <DIR>Use this tool store instead of the shared user store
$ oyzu which go
C:\Users\you\AppData\Local\Oyzu\tools\installs\282fe8f87e7cea5bdeaeff96e33f205b3328f0eaf7f249a1d58e852f7445a739\payload\bin/go.exe

The output is just the path, so it works in scripts: "$(oyzu which go)" version. With --json: {"command":"go","path":"…"}.

oyzu env​

oyzu env [OPTIONS]
OptionDescription
--store <DIR>Use this tool store instead of the shared user store
--shell <SHELL>Print code that applies the environment to this shell instead of describing it [possible values: bash, zsh, pwsh]

(The inherited PATH entries are trimmed with ….) Values whose names look like credentials (token, secret, password, key and similar) are redacted in this view. Inspection never changes your shell.

Apply it once to the current shell​

$ oyzu env --shell pwsh
${Env:PATH}='C:\Users\you\AppData\Local\Oyzu\tools\installs\282fe8f87e7cea5bdeaeff96e33f205b3328f0eaf7f249a1d58e852f7445a739\payload\bin;…'
${Env:GOROOT}='C:\Users\you\AppData\Local\Oyzu\tools\installs\282fe8f87e7cea5bdeaeff96e33f205b3328f0eaf7f249a1d58e852f7445a739\payload'
${Env:GOTOOLCHAIN}='local'

(The PATH value is trimmed with …; the real line lists every entry.) Evaluate it to apply the values (oyzu env --shell pwsh | Out-String | Invoke-Expression, or eval "$(oyzu env --shell bash)"). This is a one-shot change with no directory hook and no automatic undo; use oyzu activate when you want the environment to follow you between projects. Explicitly requested shell code contains actual values, including any secrets in your configuration.

JSON output​

oyzu --json env returns the same facts as one record. Here the tool-store digest in each path is shortened to its first eight characters and PATH is trimmed to its first entry with ….

$ oyzu --json env
{
  "configuration": [],
  "environment": {
    "GOROOT": "C:\\Users\\you\\AppData\\Local\\Oyzu\\tools\\installs\\282fe8f8…\\payload",
    "GOTOOLCHAIN": "local",
    "PATH": "C:\\Users\\you\\AppData\\Local\\Oyzu\\tools\\installs\\282fe8f8…\\payload\\bin;…"
  },
  "executable": "C:\\Users\\you\\AppData\\Local\\Oyzu…ls\\installs\\282fe8f8…\\payload\\bin/go.exe",
  "executables": {
    "go": "C:\\Users\\you\\AppData\\Local\\Oyzu\\tools\\installs\\282fe8f8…\\payload\\bin/go.exe",
    "gofmt": "C:\\Users\\you\\AppData\\Local\\Oyzu\…ls\\installs\\282fe8f8…\\payload\\bin/gofmt.exe"
  },
  "projectEnvironmentSkipped": false,
  "tool": "oyzu:go",
  "tools": {
    "oyzu:go": "C:\\Users\\you\\AppData\\Local\\Oyzu…ools\\installs\\282fe8f8…\\payload\\bin/go.exe"
  },
  "unset": []
}

projectEnvironmentSkipped is true in an untrusted folder, where project [env] values are shown but not applied by shells, shims and exec. With --shell, --json returns { "shell": …, "script": … }; evaluate the raw script, never the JSON.

Exit status and errors​

StatusWhen
child's statusoyzu exec returns the command's own exit status
0which found the command; env succeeded
1The command is not in the selection, or a selected tool is not installed
4The lock is missing or stale for a requirement

CodeFix
COMMAND_NOT_FOUNDDeclare and install the tool that provides the command (oyzu install go@1.26), or check the spelling.
TOOL_INSTALLATION_MISSINGThe lock selects a tool that is not in the store. Run oyzu install.
TOOL_LOCK_STALE / TOOL_LOCK_MISSINGRun oyzu pin, then oyzu install.
