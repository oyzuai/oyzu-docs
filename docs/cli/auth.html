oyzu auth

Sign in to an Oyzu platform account, check the local session or sign out. Only the platform commands (oyzu build --remote, oyzu run --remote, oyzu secrets, oyzu release check) use the session. Everything else Oyzu does stays local and needs no account.

oyzu auth [OPTIONS] <COMMAND>
SubcommandWhat it does
loginSign in by approving a code in a browser, then store the session
statusShow the selected platform, account and local session state; asks no server
logoutEnd this account's local session and ask the issuer to revoke it
conformanceRun the client authentication conformance suite against a local fake issuer; needs no account

None of the subcommands has options of its own; the global options apply.

Status

Experimental client. Verified against a local conformance fake only; not yet run against a real identity provider, a real platform or each operating system's credential store. Until a platform serves the required metadata, login reports discovery as unsupported (platform sign-in).

Set up​

Point Oyzu at the platform and account in your user configuration (a project file cannot choose where credentials go):

oyzu config set --global platform.url https://platform.example.com
oyzu config set --global platform.account payments

Without this, login, status and logout stop at once (conformance needs no configuration):

$ oyzu auth status
✗ AUTH_NOT_CONFIGURED: set platform.url to the platform URL, for example `oyzu config set --global platform.url https://platform.example.com`
  Next: Correct the reported cause and retry the command.

oyzu auth login​

oyzu auth login

Uses the OAuth 2.0 device authorization grant (RFC 8628). Oyzu discovers the platform's issuer from platform.url, shows a verification address and a short code to approve in any browser on any device, checks that you are an active member of platform.account, and only then stores the session in the operating system's credential store: macOS Keychain, Windows Credential Manager or a Linux Secret Service provider. There is no plaintext fallback. A cancelled, denied or expired login stores nothing.

login needs a terminal; without one it fails with AUTH_INTERACTION_REQUIRED before any request. The code is printed on standard error, so --json output stays parseable.

oyzu auth status and oyzu auth logout​

status reads local state only and reports the platform, account and session state: absent, active, refreshing, reauthentication-required or logged-out. logout deletes this account's local session, then asks the issuer to revoke it and reports that result separately (remote: refused, unreachable or not-advertised when revocation could not be confirmed).

oyzu auth status --json
oyzu auth logout

Which credential a command uses​

SituationCredential
OYZU_PLATFORM_TOKEN is setThat token, as supplied
At a terminal, no token setThe stored session from oyzu auth login
Unattended (CI, scripts, agents), no token and no provider selectedNone: AUTH_PROVIDER_REQUIRED. A stored session is never used implicitly

platform.authentication.provider (session or environment) selects one explicitly. The credential is sent only to the origin of platform.url.

oyzu auth conformance​

Checks this client's sign-in behavior against a local fake issuer with synthetic credentials. It needs no account or network:

Exit status and errors​

0 on success and 1 on any failure. Common codes:

CodeFix
AUTH_NOT_CONFIGUREDSet platform.url and platform.account with oyzu config set --global.
AUTH_INTERACTION_REQUIREDRun login from a terminal. In CI, supply OYZU_PLATFORM_TOKEN instead.
AUTH_STORE_UNAVAILABLEStart or unlock the operating system's credential store.
AUTH_NOT_A_MEMBER, AUTH_STEP_UP_REQUIREDYour identity is not an active member of platform.account, or the account needs stronger authentication. Nothing was stored.
AUTH_DISCOVERY_UNSUPPORTEDThe platform does not publish the sign-in metadata yet.
AUTH_REAUTHENTICATION_REQUIRED, AUTH_LOGIN_REQUIREDRun oyzu auth login again.
