oyzu config

Inspect, explain and edit Oyzu's configuration. Settings come from a cascade: built-in defaults, machine and user configuration, every oyzu.toml from the repository root down to the target's folder, then oyzu.local.toml. oyzu config shows the merged result and where each value came from, and edits one file at a time. build.yaml (which builds exist) is a separate file; see discover.

oyzu config [OPTIONS] <COMMAND>
SubcommandWhat it does
showShow the resolved configuration
getRead one resolved configuration value
explainExplain where configuration values came from
profilesList available configuration profiles
validateValidate configuration and report diagnostics
statusShow configuration session status
refreshRefresh the configuration session
setSet a value in one chosen configuration file
unsetRemove a value from one chosen configuration file
schemaPrint the JSON Schema of build.yaml or oyzu.toml, for editors

Every subcommand accepts the global options. --profile NAME resolves (or, for set, writes into) that profile; --root and -C choose the project.

config get​

oyzu config get [OPTIONS] <KEY>
Argument / optionDescription
<KEY>The setting, such as build.jobs
--globalRead only the user configuration file, without merging other scopes
--projectRead only oyzu.toml in the selected directory
--localRead only oyzu.local.toml in the selected directory
oyzu config get build.jobs           # 4
oyzu --json config get build.jobs    # 4, as a bare JSON value

With --json, the output is the bare JSON value, which is handy in scripts. A key with no effective value fails with CONFIG_INVALID_VALUE: setting has no effective value.

config profiles​

oyzu config profiles

Lists the available profiles and which one is selected, and why. A profile is a named set of settings, selected with --profile, OYZU_PROFILE or a project default. CI selects the built-in ci profile automatically. Profiles never grant extra permissions and can't hold tools (use a toolset for that).

config validate​

oyzu config validate [OPTIONS]
OptionDescription
--strictFail on warnings too, listing each with its key, source and fix
--all-profilesValidate every profile, not only the selected one
$ oyzu config validate
Configuration
​
Diagnostics:
  (none)
Valid: yes

show and explain can succeed with Status: unresolved, so use validate as the configuration gate in automation. It exits non-zero on a validation failure.

For builds that use an external builder plugin, validate checks the plugin's declared profile, required engine features and the general shape of with, using the installed package metadata. It never runs the plugin or refreshes the plugin catalog. The package must already be installed by a normal build; otherwise you get PLUGIN_NOT_ADOPTED or PLUGIN_NOT_INSTALLED with the next step. Plugin-specific option values are checked by the build itself.

config status and config refresh​

oyzu config status
oyzu config refresh

status reports whether this machine is enrolled in managed configuration and the state of its policy cache, without going online. In standalone use it prints Enrolled: no and Mode: standalone. refresh fetches managed policy and reports its revision and offline deadline. It needs managed enrollment; standalone, there is nothing to refresh.

config set and config unset​

oyzu config set [OPTIONS] <--global|--project|--local> <KEY> <VALUE>
oyzu config unset [OPTIONS] <--global|--project|--local> <KEY>
OptionDescription
--globalSelect the user (global) configuration file
--projectSelect oyzu.toml in the selected directory
--localSelect oyzu.local.toml in the selected directory
--json-value(set only) Parse VALUE as JSON, for arrays and objects

Exactly one scope flag is required:

$ oyzu config set --project build.jobs 4
Configuration
​
Destination: …\hello\oyzu.toml
Updated: build.jobs
  • Booleans and numbers are parsed by type; strings are taken literally.
  • Edits keep unrelated comments and formatting, check known keys and types, and replace the file in one step.
  • unset removes the value from that file so inherited values show through.
  • Only an explicit --profile NAME writes into a profile.
  • Tools aren't settings. Use oyzu install to declare them.

Leaving out the scope flag is a usage error (CLI_USAGE, exit 2).

config schema​

Prints the JSON Schema of build.yaml or oyzu.toml for editor completion and validation. It opens no project and needs no network.

oyzu config schema [OPTIONS] [FILE]
ArgumentMeaning
[FILE]The file whose schema to print: build.yaml or oyzu.toml

Without a file name, it lists both schemas and where each release publishes them:

  • https://github.com/oyzuai/oyzu-releases/releases/latest/download/build.yaml.schema.json
  • https://github.com/oyzuai/oyzu-releases/releases/latest/download/oyzu.toml.schema.json

oyzu discover --write adds a # yaml-language-server: $schema=<URL> line to build.yaml; add it by hand to an existing file. For oyzu.toml, point Taplo or Even Better TOML at the URL. Offline, save the schema and point your editor at the file:

oyzu config schema build.yaml > build.yaml.schema.json

With a file name, the schema itself is printed, even in human mode, so you can redirect it. With --json, it is wrapped in a config-schema record under schema.

Exit status​

StatusWhen
0Success (show and explain succeed even when the status is unresolved)
1refresh failed, or another operation error
2Missing scope flag or other invalid arguments
3Invalid configuration, a key with no value (CONFIG_INVALID_VALUE), a setting in the wrong scope (CONFIG_SCOPE), or a validation failure

Common configuration codes:

CodeFix
CONFIG_SYNTAXThe TOML is malformed. The message gives file:line:column; fix it in an editor.
CONFIG_UNREADABLEA configuration file exists but your account can't read it, usually because of its permissions. Grant read access to the named file, then retry.
CONFIG_SCOPEA project file sets something it may not, such as cache.dir. Move it to user configuration.
CONFIG_EDIT_CONFLICTAnother process edited the file at the same time. Retry.
CONFIG_PROFILE_TOOLSA profile contains tools. Use a toolset instead.
