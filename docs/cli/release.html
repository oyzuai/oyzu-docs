oyzu release and oyzu secrets

Two platform commands. oyzu release check asks an Oyzu platform whether the build in dist/ would ship, environment by environment, before anything is published. oyzu secrets manages the account's secrets, whose values you can write but never read back.

Both need a platform account: platform.url and platform.account in user configuration, and a credential from oyzu auth login (at a terminal) or the OYZU_PLATFORM_TOKEN environment variable.

Note: Both commands are experimental, and release check isn't available on deployed platforms yet.

oyzu release check​

oyzu release check [OPTIONS]
OptionDescription
--project <PROJECT>The project to check in (or OYZU_PROJECT)
--environment <ENVIRONMENT>Answer for this environment only; repeat for more. Default: every environment
--manifest <FILE>The build manifest to check. Default dist/manifest.json
--version <VERSION>Use this version for every component, instead of each artifact's own
--commit <SHA>The built commit; defaults to the checkout's HEAD

The global options also apply.

Run it after oyzu build. It sends the manifest's artifacts to the platform, which works out the plan a release of them would get now and answers for each environment: would ship, would wait (naming each approval, gate or blocker), or refused (naming the policy). Nothing is published, saved or started.

oyzu build
oyzu release check --project web
oyzu release check --project web --environment production
oyzu release check --project web --json

The answer has one line per environment (✓ qa would ship, … production would wait, ✗ eu would refuse it), each reason with its policy underneath, and, when a start policy covers the build, whether publishing would join an open batch or start a release. --json prints the platform's ship-check record with account added.

StatusWhen
0No environment would refuse the build (waiting on a person or gate isn't a failure)
1An environment would refuse it, or the check couldn't be made
CodeFix
RELEASE_CHECK_NOT_CONFIGUREDPass --project (or set OYZU_PROJECT) and set platform.url and platform.account.
RELEASE_CHECK_UNAUTHENTICATEDRun oyzu auth login from a terminal, or set OYZU_PLATFORM_TOKEN.
RELEASE_CHECK_NO_COMMITThis isn't a Git checkout with a commit. Pass --commit.
RELEASE_CHECK_NOTHING_TO_SHIPThe manifest lists no artifacts.
PUBLISH_BUILD_NOT_SUCCEEDEDThe manifest records a build that didn't succeed.

oyzu secrets​

oyzu secrets [OPTIONS] <COMMAND>
SubcommandWhat it does
listList a scope's secrets: names, exposure and value versions, never values
create <NAME>Create a secret without a value; set one with oyzu secrets set
set <NAME>Set or replace a value from standard input, a file, or a generated value shown once
rm <NAME>Delete a secret and all its values, or end its overlap with --previous

No command ever shows a stored value, and a value is never taken from the command line, where it would end up in your shell history.

Options​

Every subcommand takes a scope; without one it acts on the account:

OptionDescription
--org <ORG>An organization of the account, by identifier
--project <PROJECT>A project of the account, by identifier

create:

Argument / optionDescription
<NAME>Lowercase letters, digits and hyphens
--exposure <EXPOSURE>Required. What may ever receive the value: a platform service (internal) or a job's runner (build)
--type <TYPE>text (UTF-8, the default) or file (exact bytes)
--description <DESCRIPTION>A short note shown in listings

set:

Argument / optionDescription
<NAME>The secret's name (or ID)
--file <PATH>Read the value's exact bytes from this file instead of standard input
--generateGenerate 32 random bytes (as 64 hex characters), set them and print them once
--overlap <DURATION>Keep the replaced value valid this long, such as 24h (at most 168h)

rm:

Argument / optionDescription
<NAME>The secret's name (or ID)
--previousRetire only the previous value now, keeping the secret

Examples​

oyzu secrets list                                       # the account's secrets (never their values)
oyzu secrets create release-webhook --exposure internal
oyzu secrets set release-webhook --generate             # make a webhook secret and show it once
oyzu secrets set npm-token --project web < token.txt    # set a value from standard input
oyzu secrets set deploy-key --file key.pem --overlap 24h
oyzu secrets rm release-webhook --previous              # end an overlap now

--overlap keeps the old value valid while consumers move to the new one; rm --previous ends the overlap early. A create, set or delete is sent once and never retried automatically. If one fails in transit, run oyzu secrets list to see what happened before you retry.

Exit status and errors​

Exits 0 on success and non-zero on any failure; the error code names the cause.

CodeFix
SECRETS_NOT_CONFIGUREDSet platform.url and platform.account.
SECRETS_UNAUTHENTICATEDRun oyzu auth login, or set a current OYZU_PLATFORM_TOKEN.
SECRETS_PERMISSION_DENIEDYou aren't allowed to manage secrets in that scope.
SECRETS_NOT_FOUNDNo secret with that name in the scope. Create it first with oyzu secrets create.
SECRETS_RESOURCE_CONFLICTThe name is taken, there's no previous value to retire, or the platform manages the secret.
SECRETS_VALUE_REQUIRED, SECRETS_VALUE_EMPTY, SECRETS_VALUE_TOO_LARGEGive a non-empty value on standard input, with --file or with --generate.
SECRETS_OVERLAP_INVALIDUse a duration such as 24h or 90m, at most 168h.
