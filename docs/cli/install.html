oyzu pin, install, update, uninstall and reshim

These commands manage which tool versions a project requires and has locked. Two files work together:

  • oyzu.toml says what you asked for, as you typed it (go = "1.22"), in the [tools] table.
  • oyzu.lock records the exact version and verified archive for every platform (1.22.12, with URL and SHA-256 for Linux, macOS and Windows). Commit it.
CommandChanges oyzu.tomlChanges oyzu.lockDownloads and installs
oyzu pinonly with named toolsyesno
oyzu install (no arguments)nocan add missing entries; never with --frozenyes
oyzu install TOOL@VERSIONyesyesyes, for this machine
oyzu updateneveryesyes, for this machine
oyzu uninstall TOOLyesyesno (installed files stay in the store)
oyzu reshimnonono (refreshes shims only)

Tools Oyzu installs today: node, go, python, java, maven, gradle, helm, kubectl, k3d, liquibase, tailscale, npm, pnpm, rust, the Cargo helpers cargo-nextest and cargo-llvm-cov, and (experimentally) registry packages from the tool index. No account is needed. The tool commands are implemented and verified on Linux x86-64; the examples on this page ran on Windows (tool commands status).

oyzu pin​

Read what the project's builds need (from native files such as go.mod, package.json engines or rust-toolchain.toml, and from oyzu.toml), pick concrete versions and record them in oyzu.lock. It never installs anything.

oyzu pin [OPTIONS] [TOOL[@VERSION]]...
ArgumentMeaning
[TOOL[@VERSION]]...Declare and lock these tools without installing (omit for discovered requirements)
OptionDescription
--dry-runPreview discovered requirements and lock changes without writing files
--refreshRefresh installation recipes while preserving selected tool versions
--offlineResolve from existing locks and cached metadata only; no network access
oyzu pin --dry-run

Run without --dry-run and the last lines become Tool resolutions pinned.; oyzu.lock now exists. Named tools (oyzu pin kubectl@1.34 helm@3.22.0) are also declared in oyzu.toml; they cannot be combined with --refresh or --offline. Bare oyzu pin also locks every toolset; oyzu --toolset NAME pin locks only that toolset.

oyzu --json pin returns the requirements, requested_versions, the proposed_files, platform compiler_metadata, diagnostics and complete. Incomplete resolution exits 1.

oyzu install​

oyzu install [OPTIONS] [TOOLS]...
ArgumentMeaning
[TOOLS]...Tools to declare and install, as [provider:]name[@version] (omit to install everything declared). Without a version, a declared tool keeps its requirement and an undeclared one takes the newest eligible version
OptionDescription
-g, --globalAct on your global (user) configuration and its lock instead of the project
--localAct on oyzu.local.toml; the lock remains the project's
--dry-runWith tools: report what would be declared, resolved and locked, and write nothing
--frozenRequire an existing matching lock without resolving new versions
--offlineUse only existing locks, installations and cached archives
--update [<UPDATE>...]Deprecated alias for oyzu update: resolve configured requirements again
--artifact-set <FILE>Resolved artifact set (JSON) that supplies a registry tool (oyzu:NAME@VERSION); repeatable. Without --artifact-set-digest the set is local and anchored by you
--artifact-set-digest <sha256:DIGEST>Pin a set record by its digests.full; repeatable (provisional flag)
--connector-bindings <CONNECTOR_BINDINGS>Host-owned connector endpoints and authorization environment references
--store <DIR>Use this tool store instead of the shared user store

Version forms: go@1.26 is a prefix, go@1.26.8 is exact, go@latest is the newest eligible version, and plain go keeps an existing declaration (or takes the newest when undeclared).

Install everything the project declares​

On a fresh clone, this is the one command a teammate needs:

oyzu install
Installing tools
Checking pinned tools and verifying reusable installations
Tool installation

Tool  Version  Result
go    1.22.12  reused

Selected installations verified. Use oyzu tools current to inspect availability.

In CI, oyzu install --frozen fails instead of resolving anything new when the lock does not match.

Add a tool to the project​

Preview first:

oyzu install go@1.22 --dry-run
Installing requested tools
Resolving every platform, then installing this one
Dry run · no files were changed
✓ Would install go 1.22.12
    Would declare "1.22" in …\hello\oyzu.toml (project)
    Locked in …\hello\oyzu.lock for 4 platforms (darwin/arm64/native, linux/amd64/gnu, linux/arm64/gnu, windows/amd64/msvc)

Store: C:\Users\you\AppData\Local\Oyzu\tools
No archive was downloaded and no file was written. Run again without --dry-run to apply.

Then apply it:

oyzu install go@1.22
Installing requested tools
Resolving every platform, then installing this one
✓ Installed (reused existing installation) go 1.22.12
    Declared "1.22" in …\hello\oyzu.toml (project)
    Locked in …\hello\oyzu.lock for 4 platforms (darwin/arm64/native, linux/amd64/gnu, linux/arm64/gnu, windows/amd64/msvc)

Store: C:\Users\you\AppData\Local\Oyzu\tools

Oyzu resolves every platform in the lock but downloads only this machine's archive. The configuration and lock are written together in one transaction: any failure leaves both unchanged. Several tools in one command are applied together or not at all.

Scope: project, local or global​

FlagConfiguration writtenLock
none, inside a projectproject oyzu.toml (created if absent)project oyzu.lock

oyzu install -g node@22     # your default Node for every project

Outside a project, the project scope fails with TOOL_NO_PROJECT instead of guessing.

oyzu update​

Move each locked version forward within its existing requirement. update never edits oyzu.toml; to change the requirement itself, run oyzu install tool@new-version.

oyzu update [OPTIONS] [TOOLS]...
ArgumentMeaning
[TOOLS]...Tools to update (omit to update every tool in the selected scope)
OptionDescription
-g, --globalAct on your global (user) configuration and its lock instead of the project
--localAct on oyzu.local.toml; the lock remains the project's
--dry-runReport the versions that would be locked and write nothing
--connector-bindings <CONNECTOR_BINDINGS>Host-owned connector endpoints and authorization environment references
--store <DIR>Use this tool store instead of the shared user store

oyzu uninstall​

Remove a tool's declaration and its lock entries at one scope. Installed files stay in the shared store, because other projects may use them.

oyzu uninstall [OPTIONS] <TOOLS>...
ArgumentMeaning
<TOOLS>...Tools to remove, by name
OptionDescription
-g, --globalAct on your global (user) configuration and its lock instead of the project
--localAct on oyzu.local.toml; the lock remains the project's
--dry-runReport what would be removed and write nothing
--store <DIR>Use this tool store instead of the shared user store
oyzu uninstall go --dry-run
Dry run · no files were changed
✓ Would remove go
    Declaration "1.22" removed from …\hello\oyzu.toml (project)
    Lock entry removed from …\hello\oyzu.lock

Installed files stay in the store and remain listed by oyzu tools list as unreferenced.
Store: C:\Users\you\AppData\Local\Oyzu\tools

Before go was declared in oyzu.toml (when the requirement came only from go.mod), the same command failed:

✗ TOOL_NOT_DECLARED: oyzu:go is not declared in …\hello\oyzu.toml (project scope). No files were changed
  Next: Check the selected directory and name; use oyzu -C <project> to select a project.

oyzu reshim​

Refresh the shims folder (small launchers named after each installed tool's commands) and any existing activation launchers. No tools are downloaded and no shell profile is edited.

oyzu reshim [OPTIONS]
OptionDescription
--store <DIR>Use this tool store instead of the shared user store

Put the reported folder on PATH for IDEs, scheduled tasks and other non-interactive programs. Each shim resolves the project it runs in. On Windows, for your user:

$shims = (oyzu reshim --json | ConvertFrom-Json).directory
[Environment]::SetEnvironmentVariable('Path', "$shims;" + [Environment]::GetEnvironmentVariable('Path', 'User'), 'User')

On Windows, install both oyzu.exe and oyzu-shim.exe before refreshing. With only oyzu.exe present, oyzu install installed the tool and then stopped at the shims step:

✗ COMMAND_FAILED: missing native launcher …\oyzu-shim.exe; install both Oyzu binaries
  Next: Correct the reported cause and retry the command.

Exit status​

StatusWhen
0Success, including dry runs
1Resolution or installation failed (for example an unknown tool name, or an unreachable publisher), or pin could not resolve everything
2Invalid combination of arguments, such as a tool spec with --frozen (TOOL_FLAGS_CONFLICT), or an unparseable spec
3tools.allowed or policy refuses the tool, or a version is below a native minimum (TOOL_NATIVE_MINIMUM_CONFLICT)
4The lock is missing or stale (TOOL_LOCK_MISSING, TOOL_LOCK_STALE)
5TOOL_NOT_DECLARED or TOOL_NO_PROJECT

Common errors​

$ oyzu install go@1.22 --frozen
✗ CLI_USAGE: TOOL_FLAGS_CONFLICT: a tool spec resolves versions online and cannot be combined with --frozen, --offline or --update
  Next: Run oyzu <command> --help for supported arguments.

$ oyzu install nosuchtool@1 --dry-run
✗ TOOL_NAME_UNKNOWN: nosuchtool is not a known short name (catalog 2026.10.5); name the package explicitly, for example oyzu:<owner>/<repo>
  Next: Correct the reported cause and retry the command.
CodeFix
TOOL_FLAGS_CONFLICTSpecs resolve online; --frozen, --offline and --update work only without specs. Run two commands.
TOOL_NAME_UNKNOWN, TOOL_ALIAS_UNSUPPORTEDUse a supported name (oyzu tools info NAME lists them) or a full registry name.
TOOL_LOCK_STALEThe lock lacks a pin for a requirement, often after go.mod or package.json changed. Run oyzu pin, then oyzu install.
PIN_EDIT_CONFLICT, CONFIG_EDIT_CONFLICTAnother process edited the files at the same time. Retry.
PIN_RECOVERY_REQUIREDAn interrupted edit left a journal. Run oyzu install or oyzu pin in that folder to recover it.
