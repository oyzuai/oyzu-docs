Build Java projects

Oyzu builds Maven reactors and Gradle builds from pom.xml and build.gradle alone. It provisions the JDK and Maven or Gradle itself, runs your native lifecycle, collects JUnit and JaCoCo reports and records the jars it produced. You do not need Java installed, and you do not write an Oyzu build file.

Java support is experimental. Maven and Gradle build natively on your machine; Ant needs the isolated executor. The limits are listed at the end.

Every output block below is a real capture from Windows 11 with a development build of the CLI (0.1.0-local.564f462704df), color forced on and output piped to a file. Long local paths are shortened to …. Times, hashes and versions on your machine will differ.

What Oyzu detects​

Signal in your projectWhat it decides
pom.xmlA java/maven target. A reactor (parent POM with <modules>) is one target; Maven owns module order, inheritance and profiles
build.gradle or build.gradle.ktsA java/gradle target. A multi-project build, including includeBuild composites, is one target; Gradle owns membership and task dependencies
build.xmlAn Ant target, built only in the isolated executor
mvnw or gradlew committedThe wrapper is run instead of mvn or gradle, and Oyzu provisions only the JDK
maven.compiler.release, maven.compiler.target, maven.compiler.source or java.version in the root POMThe minimum JDK
JavaLanguageVersion.of(…) or sourceCompatibility in Gradle build scriptsThe minimum JDK

Discovery reads files only; it does not start Maven or Gradle.

Oyzu reads Gradle's own model through an Oyzu-supplied init script, which reports each project's archive and test tasks, then runs gradle --no-daemon build with an init script (-I) that applies JaCoCo. Tests and coverage​

No test or report configuration is needed.

  • Maven: verify runs Surefire and, where the module declares maven-failsafe-plugin and has IT*, *IT or *ITCase classes, Failsafe. Each module with test sources owes its JUnit XML from target/surefire-reports (and target/failsafe-reports). JaCoCo 0.8.13 runs around verify, and each module's target/site/jacoco/jacoco.xml is collected.
  • Gradle: build runs your Test tasks. Each tested project's JUnit results and the JaCoCo report the init script writes under build/reports/oyzu/<test task>/jacoco.xml are collected.

A failing test fails the build with the native output and publishes no jars. A module with test sources but no XML (for example because tests were skipped) fails its report obligation; Oyzu never invents a passing report.

To run only the tests on your machine and collect the same reports into a test-only bundle, use oyzu run test followed by oyzu inspect dist. That path needs Maven or Gradle and the JDK already provisioned and runs Maven or Gradle offline; see Maven and Gradle.

Lint and formatting​

lint and format-check are build stages selected by --full (or a CI context). The defaults are Checkstyle 10.21.4 (unused and redundant imports, empty statements, equals/hashCode consistency) and google-java-format 1.28.0. They check .java files under the target, skipping target, build, .gradle, out, dist and similar directories. format rewrites files and only runs when you ask: oyzu run format.

Oyzu does not download these two tools yet. On a fresh machine, --full stops before building:

You have three ways forward, all named in the message:

  1. Provision the defaults. From a checkout of the Oyzu repository, run python tooling/provision-java-quality.py --destination <absolute directory>. It downloads checksum-pinned upstream JARs. Then set OYZU_JAVA_QUALITY_HOME to that directory (export OYZU_JAVA_QUALITY_HOME=/opt/java-quality, or $env:OYZU_JAVA_QUALITY_HOME = 'E:\tools\java-quality' in PowerShell).

  2. Use your own quality tasks. If the project already has Checkstyle or Spotless configured, replace the defaults in oyzu.toml. The tasks must exist in your build:

    [tasks.lint]
    argv = ["gradle", "--no-daemon", "checkstyleMain", "checkstyleTest"]

    [tasks.format-check]
    argv = ["gradle", "--no-daemon", "spotlessCheck"]

  3. Build without --full until either is in place.

Oyzu does not yet infer Maven quality-plugin bindings or Gradle quality tasks, read your own Checkstyle XML, or run Kotlin or Groovy linters. See Java quality.

Choose the JDK, Maven and Gradle​

Native files come first, then oyzu.toml, and the result is always recorded in oyzu.lock.

ToolDefault requestOverride
JDKThe declared Java level (maven.compiler.release and friends, or the Gradle sourceCompatibility/toolchain level), raised to 17 if lower; lts when nothing is declared[tools] java
Maven3.9[tools] maven
GradleGradle 8, or 9 when the project declares a Java level above 24[tools] gradle

The declared level is a floor: a project declaring release 21 gets JDK 21, not the newest JDK. A project declaring 8 or 11 gets JDK 17, the oldest JDK Maven, Gradle and Oyzu's Java integration run on; JDK 17 compiles the older level faithfully with --release. To choose explicitly:

[tools]
java = "21"       # latest 21.x, "lts", or an exact "21.0.8"
maven = "3.9"     # or gradle = "8"

oyzu pin --dry-run previews what would be locked. oyzu exec -- mvn -version runs a command with the locked tools. JDKs are Eclipse Temurin, verified against the SHA-256 that the Adoptium API declares; Maven comes from the Apache distribution server and Gradle from services.gradle.org, each verified against its published digest. A build sees JAVA_HOME, MAVEN_HOME and GRADLE_HOME from these tools only; a machine-wide JDK is never inherited. See Java, Maven and Gradle installation.

Wrappers. With a committed mvnw or gradlew, Oyzu runs the wrapper and provisions only the JDK. The wrapper downloads its own Maven or Gradle outside Oyzu's verification, so pin distributionSha256Sum in maven-wrapper.properties or gradle-wrapper.properties. The Maven wrapper's only-script form also needs curl or wget on PATH.

Artifacts​

ProjectWhat lands in dist/<target>/artifacts/
Maven reactor (native build)Each module's jar, with its native name, such as library-0.1.0-SNAPSHOT.jar
Gradle build (native build)Each archive Gradle's model reports, such as app.jar and support-0.1.0.jar; same-named archives are qualified by project path
Isolated Maven or Gradle buildpom, jar and war (Maven) or JAR, WAR, EAR, ZIP and TAR archives (Gradle), with snapshot versions projected from version inference into private copies of your build files

dist/manifest.json records every artifact with its digest, the tests and coverage and the logs; oyzu inspect dist verifies them. A build artifact is not a publication or release approval.

Where Java builds run​

oyzu build runs Maven and Gradle on your machine when the project fits the native profile:

  • Maven: a reactor whose jar names can be read from the POMs (literal or inherited versions, jar packaging, no finalName or classifier).
  • Gradle: any build whose archives Gradle's model reports.

Everything else, and every Ant project, uses the isolated executor: a Linux container with captured dependencies and no network during the build. It needs Docker and the Maven, Gradle or Ant toolchain image, which you build yourself as described in the Maven, Gradle and Ant references; those images are not published yet. Request the isolated path explicitly with oyzu build --isolated, for example oyzu build --isolated --full for Gradle. The isolated worker restores the JDK locked in oyzu.lock instead of the image's JDK 17, and refuses a selected JDK older than 17 with TOOL_UNSUPPORTED_VERSION.

Common failures and fixes​

SymptomCauseFix
Java lint and format-check need Checkstyle and google-java-format…--full without provisioned quality toolsProvision them and set OYZU_JAVA_QUALITY_HOME, replace the tasks, or build without --full (above)
Build fails with a JUnit failure and no jars in OutputsA test failed; jars are never published from a failing buildFix the test. The Surefire output and log path are in the failure section
A module fails its report obligationTest sources exist but no JUnit XML was produced (skipped tests, disabled reporting, or a custom report directory)Let the tests run, or move reports to the default directory; custom report directories are not collected on the native path
Dependency or JaCoCo download failsMaven Central throttled or was unreachable; coverage tooling is fetched by Maven or GradleRetry. --offline builds need those artifacts already in the local repository
TOOL_UNSUPPORTED_VERSIONAn isolated build selected a JDK below 17Remove the low [tools] java pin; JDK 17 compiles older --release levels
Ant build refused before any workNo Docker, and Ant has no native host buildStart Docker and provision the oyzu-toolchain/ant image
Gradle refuses the daemon JDK vendorgradle-daemon-jvm.properties names a vendor other than Adoptium (isolated path)Use Temurin, or provision a matching runtime yourself

For anything else, start with the Log path in the failure section and Troubleshooting.

Limits​

  • The native builds have their recorded qualification on Linux x86_64 (2026-10-07). The runs on this page succeeded on Windows 11 for the default build; the Windows mvn.cmd launcher and JDK zip are otherwise unverified, and macOS is unverified.
  • Java quality tools are not provisioned automatically.
  • Private or custom Maven repositories and corporate credentials are not supported; dependencies come from Maven Central (and, for Gradle plugins, the Gradle plugin portal).
  • Custom JaCoCo destinations, aggregate reactor coverage and custom test report directories are not collected.
  • The isolated toolchain images must be built by hand.
  • A green build is evidence that these stages passed on this source. It is not a release approval.
